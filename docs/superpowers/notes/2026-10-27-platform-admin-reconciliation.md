# Platform Admin: design vs. built reconciliation and spec backlog

Date: 2026-10-27. Planning artifact only; no product code. Status: proposal for approval.

Precedence: the separation spec (`docs/superpowers/specs/2026-10-25-platform-and-tenant-admin-app-separation-design.md`) wins over the UX brief (`docs/design/2026-10-26-platform-and-tenant-admin-ux-brief.md`), which wins over the prototype where they differ. The prototype (`dev-kit/design/admin-apps/src/{platform,platform2,pctx,shared}.jsx`, `platform-data.js`) is the design truth for layout, copy and states, and is to be re-implemented on Mural (imperative `.ts` views, `Observable` VMs, Allman, no inline literals, PascalCase public methods). It is not a React port. The UX rationale (`dev-kit/design/admin-apps/docs/ux-rationale.md`) records one open assumption to confirm with the owner: a withdrawn version keeps running where already adopted.

Sources for "built": portal `pragmatic-server/admin/portal/src/*` (2326 lines, 23 files) and control plane `pragmatic-server/admin/control-plane/*`. Abbreviations: P = `platform.jsx`, P2 = `platform2.jsx`, S = `shared.jsx`, PC = `pctx.jsx`, CPH = `control-plane-host.ts`, ACH = `agent-channel-host.ts`, PDR = `platform-deployment-registry.ts`.

## 0. What exists today

Portal shell (`app.ts`): a bare `StackPanel` with a title, a Logout button and a swap-in host. There is no left nav, no top bar (context, search, theme, operator menu), no page header/breadcrumb/tabs component, no Fleet home. It boots to the legacy dev-environment list (`environment-list-view.ts`), which has a "Clients" button leading into Clients, then Tenants (per client), then Hives (per tenant). So the IA is a drill-down chain, not the designed nine-item nav. Views are plain `TextBlock` rows plus `Button`s (`portal-view-base.ts`); there is no table, status pill, banner, dialog/drawer, toast, skeleton or empty/error component. Delete uses an inline "Confirm" button, not name-to-confirm.

Built screens: `login-view.ts` (operator login, masked password), `client-list`/`create-client`, `tenant-list`/`create-tenant`, `hive-list`/`create-hive`, and the legacy `environment-list`/`environment-detail`/`graph-list`/`create-graph`/`promote-graph` (dev-edit environment tooling, not in the Platform Admin design; see section 5). `api-client.ts` exposes Login/Logout/Session, environments, clients, tenants, hives CRUD, graphs/promote, and a ticketed events socket (`/api/events-ticket`, `environments-changed` only). It has no manifest, gating, rollout, registration, health or operator calls.

Control plane (`CPH`): `/api/{login,logout,session,events-ticket,operators(POST)}`, `/api/{clients,tenants,hives}` CRUD, `GET /api/hives/:id/health` (latest hive observation), `POST /api/manifests` (publish), `POST|DELETE /api/manifests/:v/withdrawn` (withdraw/restore), `/api/{tenants|hives}/:id/{manifests,gating[/:v],rollout,rollout-registration}`, plus environments/graphs. Operator RBAC is `OperatorAuthorization` (`operator-authorization.ts`): ReadOnly is denied every non-GET except logout, returning 403 "Operator role does not permit this action". Agent channel (`ACH`): separate listener, five bearer routes `/agent/hives/:id/{target,snapshot,adoptable,status,adopt}`.

## 1. Per-screen reconciliation (brief 4.3)

Today only `POST /api/{hives}/:id/rollout-registration` exists, which mints a new raw token and overwrites the stored hash (effectively "re-issue", raw token in the response with `Cache-Control: no-store`).

### 1.5 Provisioning: "Stand up a hive" bootstrap wizard
- Designed (P `Provision`; screenshots `platform-bootstrap.png`, `platform-hive-reissue.png`): five steps. "Client & tenant" (validates 1:1: "This tenant already has a hive. One tenant, one hive."). "Target cluster" (cluster name, namespace, region/platform, base domain with help "Environments are served at https://<environmentId>.<baseDomain>/app/…"; note "Requires Kubernetes 1.28 or later and outbound HTTPS to channel.pragmatic.run:443"). "Review" (bootstrap contents: manifest + Helm chart for agent/Tenant Admin/IdP, one-time agent token shown once, pull-only registry credential by reference, trust-root public key). "Bootstrap" (success banner; bundle download with name, size, digest; RBAC the client must grant; copy-paste install commands; trust-root public key + fingerprint; registry credential reference; `OnceSecret` "Shown once" token with "I've stored it securely" gate, then closed state "…is no longer retrievable"). "First dial-in" (waiting stepper: bootstrap generated, client applies, hive reports; "Nothing to do here until then… blocked outbound HTTPS"). Status after generation: "Awaiting first dial-in". Continue is disabled until the token is acknowledged. Operator-only (denied: "hive provisioning", "the Operator role", "your operator lead").
- Built: MISSING as a wizard. The pieces exist as library code, not as an operator API: `tenant-admin-bootstrap.ts` (renders the in-hive manifest set from `TenantBootstrapInput`: tenant-admin image, channel URL, trust-root PUBLIC key, optional pull credential, IdP refs; `IHiveRegistrar.RegisterHive` mints the agent token) and `tenant-provisioning-service.ts`. `rollout-registration` mints a token. No endpoint packages a bundle; no RBAC text; no Helm chart; no digest; no "awaiting first dial-in" state.
- Delta: the whole wizard (VM with step state and validation; OnceSecret component; install-command block; stepper) plus the bundle endpoint. Backend GAP G1 (largest single item).

### 1.7 Release Policy (Gating and Selection)
- Designed (P2 `Policy`, `PolicyDrawer`; `platform-policy-edit.png`): two tabs. "Gating rules": per-scope rules (default for every hive, client, hive) with channel, minimum version, blocked versions, hold-until date plus note (change freeze), last edited by/at; "Add rule", row Edit, drawer "Edit gating" (channel, min version, blocked checkboxes, "Hold all adoption (change freeze)" toggle + date, live "Effect" section listing eligible versions or "No version is adoptable under this rule."). Empty: "Without a rule, hives may adopt any published Stable version. Add a default rule…". Toast "Policy saved. Hives receive updates…". "Adoption ledger": time, hive (link), environment (observed), from, to, outcome pill (adopted / gated out / roll failed), note (e.g. "Signature verification failed in the hive; image not served (fail-closed)"), outcome filter, row tones.
- Built: MISSING in the portal. Backend is a different model: `GatingRegistry` (`gating-record.ts`) is a per-tenant allowlist of versions (`Gate(tenantId, version)`/`Ungate`, `POST /api/{tenants|hives}/:id/gating`, `DELETE …/gating/:version`); `SelectionRegistry` holds only the LATEST target per hive (`SelectionRecord`, id = hiveId, overwritten), no history. No min-version, blocked-list, channel, hold/freeze, scope hierarchy, or editor audit. No adoption ledger and no stored gated-out/roll-failed outcomes (ACH `adopt` records a selection; a failed gate check is thrown, not stored).
- Delta: policy list/editor and ledger views. Backend GAP G5 is substantial; a minimal first slice can surface today's per-tenant allowlist and latest selection per hive, labelled honestly.

"Server" = needs control-plane work; "BLOCKED" = depends on backend that does not exist yet.
