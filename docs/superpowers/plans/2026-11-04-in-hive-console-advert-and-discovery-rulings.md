## Pre-flight findings


1. **(Major) The portal hive-console VM has no Reported phase (T8).** `PhaseOf` (hive-console-view-model.ts:869) sends any unknown wire state to Installing. As written, a `reported` status would show the installing text, poll every 2 s forever, mark the SeedingOwner row as Running (`StateAt` :924), and hide "Reinstall console", which is bound to `IsDeployed` (hives.resources.mu:857). **Recommended:** add `ConsoleInstallPhase.Reported` and `IsReported` (in BoundProperties). `IsDeployed` stays true for Deployed and Reported, so Reinstall stays visible. Map Reported in `PhaseOf`, and map it to Done in `StateAt`. `Follow` schedules `ReportPollIntervalMs` while Deployed and nothing once Reported. Add hives.resources.mu (plus its `.mu.js`) to T8 Files only if a Reported line is shown there; otherwise state that StatusText carries it. Add a test that Reinstall stays enabled when reported.
2. **(Major) A reinstall shows Reported at once from the previous install's advert (T4).** Nothing forgets the advert on reinstall or on a host change (by design), and `StatusFor` lets any same-hive advert turn a fresh Deployed into Reported, possibly with the OLD host's `consoleUrl`. The new console's first report would then never be observed. **Recommended:** when an in-memory run exists, count the advert only if `advert.reportedAt >= base.finishedAt` (Deployed) and the state is not Installing or Failed. With no run (after a restart), use the advert alone as planned. Add the test "a reinstall stays deployed until the new console reports".
3. **(Major) A tampered or wrong-key sealed entry turns every discovery into a 500 (T5).** `ConsoleFingerprintKeys.Get` throws `SealedSecretUnreadableError` (sealed-secret-store.ts:132). **Recommended:** the matcher treats a throwing key read like a missing key: skip that advert's fingerprints, keep its domains, log nothing (or the error name only). Add the test "an unreadable fingerprint key skips that advert's fingerprints".
4. **(Major) tests/desktop-discovery-compose.test.ts breaks (T5).** Its directory stub (`:79`) has only `GetTenant`. The matcher's `ListTenants` / `ListHives` calls would throw and the composed host would answer 500. T5 Step 2 runs this file, but Files does not list it. **Recommended:** add it to T5 Files and give the stub `ListTenants: () => [tenant]` and `ListHives: () => []`.
5. **(Major, security) Domain and fingerprint claims are unverified.** An in-hive tenant's Owner, or anyone holding the hive agent token (the console reuses it), can advertise another company's domain, or fingerprints of arbitrary emails computed with the hive's own key. Discovery then lists that tenant and its console for those people, which is a phishing surface. The console URL is fenced to the operator-set host, and `sharedWith` is visible only to operators. **Recommended:** accept for this plan as a recorded risk. Write it into the spec's "Accepted deviations and rulings" in T6's commit. Record each change of an advert's domain set in the control-plane audit (action plus tenant id, never the domains' emails). File "verify email-domain ownership (DNS TXT)" as a Project #1 Feature (Kind=Feature, Status=Todo).
6. **(Important) Advert forgetting must be best-effort (T4).** `ForgetHive` / `ForgetTenant` run after the hive or tenant record is already gone (control-plane-host.ts:2088, :1990, and :1544 for removal). A store write failure would turn a completed delete or removal into a 500. That is the class of bug fixed in 8c53f8d and handled for `consoleInstaller.Forget` at :2091-2101. **Recommended:** wrap each call in try/catch with `LogForgetFailure` (error name only). Add a test with a failing registry write.
7. **(Important) `ConsoleEmailDomainStore` writes a fixed `<file>.tmp` (T7).** Two concurrent `Set` calls collide, the same defect Plan 1 ruling #20 fixed in SealedSecretStore. **Recommended:** serialise `Set` through an internal promise chain and use a unique temp name (as JsonRecordStore.WriteText does, json-record-store.ts:136). Add a two-concurrent-Sets test: the last write wins, the file is valid JSON, `Changed` is emitted per real change.
8. **(Important) A Global Constraint contradicts existing code.** "Console-side code ... never imports PlatformDirectory, ControlPlaneHost or server.ts" is already false: tenant-admin-server.ts:31 imports `ControlPlaneServer`, and T7 needs `BuildTenantPlane`. **Recommended:** restate it as follows. The new console-only files (console-email-domain-store.ts, console-advert-sender.ts) and the shared files (email-domain-policy.ts, console-advert-contract.ts, tenant-api/tenant-email-domains.ts) never import platform-directory.ts (value or type), control-plane-host.ts, server.ts or platform-email-domains.ts. tenant-admin-server.ts keeps its existing server.ts import. console-advert-contract.ts may import tenant-account-index.ts, whose PlatformDirectory import is type-only.
9. **(Important) The smoke's discovery steps need a tenant-plane URL (T10).** Without `PRAGMATIC_DESKTOP_TENANT_PLANE_URL`, or the tenant-plane port and base-domain env, discovery answers 503 (server.ts:495-509). Plan 1's smoke never needed that. **Recommended:** T10 adds a preflight. One discover with a throwaway address must return 404 or 200; on 503 the smoke fails with a plain sentence naming the env var, and this counts as one of the four discover calls, so drop one later call or raise the cap to five, under the throttle of 10. Document the prerequisite in the smoke header.
10. **(Important) The self-review cites "ruling 1" (account changes), and no such ruling exists in Plan 2.** **Recommended ruling:** today the console's only sign-in account is the seeded Owner. This is the same rule TenantAccountIndex documents (tenant-account-index.ts:11-17). `SeededConsoleAccounts.Changed` never emits; this is accepted. Plan 3, and any later console account path, must emit it. Put this sentence in the `SeededConsoleAccounts` doc comment.
11. **(Minor) Duplicated homes.** (a) `ConsoleAdvertLimits.KeyBytes` duplicates `ConsoleFingerprintKeys.KeyBytes`. Drop it; `ConsoleFingerprint.ReadKeyFile` uses `ConsoleFingerprintKeys.KeyBytes`, and console-fingerprint-keys.ts only type-imports SealedSecretStore. (b) The "usable advert" rule is written three times (B9). Add one static, e.g. `ConsoleAdvertRegistry.UsableFor(lookup, hives): ConsoleAdvertRecord | undefined`, used by T4, T5 and T6. The first user is T4, so the static ships in T4 and T5/T6 consume it.
12. **(Minor) Mislabelled key.** tenant-admin-env.ts:37, tenant-admin-bootstrap.ts:57/:223/:251 and k8s-manifest-builder.ts (`TenantConsoleFingerprintVolumes` comment) call it a "session-fingerprint key", but it is the account-email fingerprint key. **Recommended:** T7, the first reader, corrects those comments (comments only, no renames).
13. **(Minor) The operator PUT body cap is 4096 (control-plane-host.ts:402).** 20 domains of up to 253 characters is about 5.2 KB, so a valid list gets a 413. **Recommended:** give the host's `ReadBody` an optional cap and use 16384 for `PUT /api/tenants/ID/email-domains`, matching the tenant route. Add one test with 20 long domains.
14. **(Minor) Advert send failures cannot be diagnosed.** Logging only `err.name` makes a 400 host mismatch and a 409 console-not-enabled read the same. **Recommended:** when the error is `ConsoleAdvertUnavailableError`, log its message (a fixed sentence plus HTTP status, never the body or token); otherwise log the name. The existing `'tok-123'` / email test still holds.
15. **(Minor) A missing email-domain route breaks whole pages.** T9 loads `GetEmailDomains` inside the Settings `Promise.all`, so a 404 (a plane built without the store, e.g. a test harness) fails the page. T8 has the same risk on the tenant detail page. **Recommended:** a 404 from the email-domain read leaves the tab or block read-only with "Email domains are not available here." Any other failure shows its sentence in the block only, never failing the page. Add one test each.
16. **(Minor) Generated `.mu.js` files are tracked.** These are admin/portal/src/sections/tenants/tenants.resources.mu.js, hives.resources.mu.js (if D1 touches it) and admin/tenant-portal/src/sections/settings/settings.resources.mu.js; `compile:mu` regenerates them during typecheck and test. **Recommended:** add them to T8 and T9 Files and stage them by path with their `.mu`.
17. **(Minor) Settings stops being read-only (T9).** The test "is read-only: it exposes no command" (settings-page-view-model.test.ts:132), the class comment (settings-page-view-model.ts:35) and the `.mu` header (settings.resources.mu:4) go stale. **Recommended:** rename the test to "the page itself exposes no command; only the Email domains editor edits" and update both comments.
18. **(Minor) The installer ctor gains a param after a defaulted one (T4).** server.ts:261-264 must now pass `new SystemInstallClock()` explicitly before `adverts`. **Recommended:** state this in T4 Step 3. Do not reorder params.
19. **(Minor) The no-receiver route order is unspecified (T3).** **Recommended:** with `adverts === undefined`, treat `console` as an unmatched segment: 404 before the bearer is checked or the body is read, the same as any unmounted route. The test "404 when no advert receiver is configured" still passes.
20. **(Minor) The "another agent edits audit-record.ts / json-record-store.ts / tests/audit-batching.test.ts" constraint looks stale.** The tree is clean apart from the untracked `docs/design/`. **Recommended:** keep the never-stage, never-revert rule (it is harmless) and drop the claim that another agent is active.
21. **(Minor) Literals where enums or constants exist.** The T2 receiver fixture uses `tls: { source: 'development' }`; use `IngressTlsSource.Development`. T6 uses `RequireCapability(res, session, 'settings')`; use `TenantApiEndpoint.SettingsCapability` (tenant-api-endpoint.ts:69). **Recommended:** apply both.
22. **(Minor) A former in-hive tenant's domains after console removal (T6).** The control-plane tenant's record `emailDomains` are seeded into the console at install (tenant-admin-bootstrap.ts:268). After the console is removed and its advert forgotten, the record's OLD domains become effective again, and the Owner's in-hive edits are lost. **Recommended:** accept and document it in the `PlatformEmailDomains` doc comment. Do not copy advert domains back into the record (that would let a hive write platform records).

No Plan 2 task conflicts with Plan 1's security rulings on admission policy, Pod Security baseline or the NetworkPolicy. Plan 2 creates no cluster objects. The console's NetworkPolicy is ingress-only (k8s-manifest-builder.ts:1271-1296), so its egress to the agent channel is unaffected. On "secrets never logged / scrubbed errors": the advert receiver, transport, sender and discovery all use fixed sentences or error names. D3 and D6 keep failures in the same scrubbed form, and D14 widens a log line only to a fixed sentence. D5 is the one security trade-off that needs an explicit ruling.
