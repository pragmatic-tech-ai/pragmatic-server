# Runtime environments on the graph engine (milestone 2, plan 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every runtime-tenant graph read and write in pragmatic-server (`cypher/query`, `cypher/models`, `cypher/execute`, `data/write`, `data/share|unshare|shares/list`, `data/assign`, `connector/*`, `model/view`, `model/resources`, `graph/load|loaded`, `application/*`) runs on ONE embedded pragmatic-graph engine per runtime environment, fed by every delivered package set, under one `AccessScope` per principal; runtime data changes are pushed; and every runtime path the switch makes dead (server and TODL) is deleted.

**Architecture:**
- **One engine-side seam for both purposes.** M1's dev classes are generalised, not copied: `IGraphEngineHost` / `IEngineSnapshot` (implemented by `DevGraphEngineHost` and the new `EnvironmentEngineHost`), `AccessScopeSource` with an `IScopeRules` strategy (dev: `DevScopeRules`, runtime: `EnvironmentScopeRules`), `EngineCypherQuery`, `EngineConnectorService`. The handler gets the same interfaces from either attach-args factory and stops branching on purpose for those endpoints.
- **Environment host.** `EnvironmentEngineHost` (inside the runtime `PragmaticServer`, which `TenantRegistry` only builds while it holds the tenant-ownership lease) composes the catalog with TODL `EnvironmentCatalogComposer` over `EnvironmentDeliveries` (every live app + the promote record), opens the engine on LMDB under the tenant's graphs root with one TODL `DataSourceConnector` per external connector plan, upgrades it in place on deploy/promote, and is disposed with the server.
- **Runtime-only services** (`src/host/environment/`): scope rules (policy files AND depth with the app-private bypass, share widening, read-only bindings, seeded nodes read-only), `EnvironmentDataWriter` (`data/write`), `EnvironmentShareService` / `EnvironmentAssignService` (grants as `todl.system.ShareGrant` nodes), `EnvironmentCypherExecute`, `EnvironmentModelView`, `DataChangedPush`.

**Tech Stack:** TypeScript (ESM, NodeNext), `tsx --test`; `@pragmatic-tech-ai/graph` 0.2.0 (M2.1), `@pragmatic-tech-ai/todl` 0.54.0 `/engine` (M2.2) → 0.55.0 (this plan), todl-identity / todl-identity-engine, pragmatic-protocol; LMDB via the engine.

## Open questions for the owner (defaults are used; nothing blocks)

- **Q1 What `application/open` binds.** **Default (S7):** the consumer app only — it must be live, it stays required for `data/*` (wire compatibility), and it changes neither the scope nor the visible catalog (spec §9: the AccessScope is the only isolation; a client-chosen binding must never relax or decide security). Should a binding instead narrow `cypher/query` to the app's package closure?
- **Q2 Two apps' policy files rule the same concept.** **Default (S5):** both apply, deny wins (AND). App B's stricter rule therefore also restricts app A's users of that shared concept (Dataverse table-level semantics). Alternative: the home app's policy only.
- **Q3 `data/write` atomicity.** **Default (S10):** the whole batch is one engine transaction (spec §6); one failing op rolls back the others (`atomic batch rolled back`). Today non-atomic bindings applied op by op.
- **Q4 `connector/decisions` (entity-identity merge audit).** The engine federates per binding and merges nothing, so there are no merge decisions. **Default (S14):** it answers `[]` and this is listed as a declared behaviour change. Should identity resolution become an engine/TODL feature (a later plan)?
- **Q5 Data-changed granularity.** **Default (S16):** concept-level (`{ commit, concepts }`), filtered to concepts the connection may read; no ids (a deleted node's visibility cannot be judged after the fact). Id-level push is a later extension.
- **Q6 `connector/writePaged` `expectedVersion`.** The engine has no read-time OCC for external rows (M2.1 D7, M2.2 Q1). **Default (S14):** an op with a non-null `expectedVersion` is `invalid` with a fixed reason; results carry no `version`.
- **Q7 Where the environment LMDB lives in a cluster.** **Default (S2):** `<graphsRoot>/environment-engine` (a local path); a deployment must put the tenant base dir on storage the next lease holder can reach. The helm chart is not changed here; ARCHITECTURE.md states the requirement.
- **Q8 Blast radius of a malformed `access-policy.json`.** **Default (S5):** every concept whose home package is one of that app's own packages fails closed (Rows and Writes False); other concepts are unaffected (today the whole bound app failed every request).
- **Q9 `cypher/execute` on runtime tenants.** **Default (S13):** enabled (spec §8 lists it), gated by the existing `writeTenant` policy and the engine scope.
- **Q10 Paging a query whose `ORDER BY` is not over returned columns.** The engine gives no `NextCursor` then (R104 cont. m2). **Default (S11):** that chain falls back to offset paging (`Skip`), so a commit between its pages may repeat or skip rows (today's behaviour for every query); declared in ARCHITECTURE.md. Alternative: refuse such a paged query with InvalidParams.

## Design rulings (record each in the implementing task's commit message and in ARCHITECTURE.md; the plan's id is the reference, e.g. "ruling S5")

- **S1 One code path.** Endpoint logic that only needs "an engine, its snapshot, a caller scope" is one class for both purposes: `EngineCypherQuery`, `EngineConnectorService`, `AccessScopeSource`, `EngineWriteFailure`, `CypherKeysetPage`, `ScopeReach`. What legitimately differs is host-shaped and stays per host: the dev `cypher/execute` (write lease, write fence, settle waits for `.todl` file writes) versus `EnvironmentCypherExecute` (no lease: the tenant-ownership lease already makes the engine single-owner, and the engine's OCC serializes); `model/view` structure (dev: the language service incl. unsaved buffers; runtime: the engine catalog). Both execute paths share placement, scope confinement and failure mapping.
- **S2 Environment host.** `EnvironmentEngineHost` opens lazily on first use: `GraphEngine.Open({ Description: catalog.Description, Storage: { Kind: options.environmentEngineStorage ?? StorageKind.Lmdb, Path: join(graphsRoot, EnvironmentEngineHost.StoreDir /* 'environment-engine' */) }, Connectors: one DataSourceConnector per catalog.Connectors entry, PrepareTimeoutMs: EnvironmentEngineHost.PrepareTimeoutMs /* 30000 */ })`. With no deliveries it still opens (the composer always adds `todl.system`). The catalog is `EnvironmentCatalogComposer.Compose({ Deliveries: await deliveries.Current(), Packages: new StoragePackageSource(packages) })`; each connector is `DataSourceConnector.Open(plan, adapters, services, catalog.Identity, catalog.Description)` (the connector borrows its adapter from the process-wide `DataSourceAdapterCatalog` and never disposes it, R112). A `GraphError` with `GraphErrorCode.Locked` at Open is retried `OpenAttempts = 3` times with `OpenBackoffMs = 500` (×2) — the previous lease holder may still be closing — then fails the request. `Redeliver()` recomposes; when `ConnectorSetKey.Of(catalog.Connectors)` (sorted JSON of each plan's `Name` and `Spec`) is unchanged it calls `engine.Upgrade(description)`, else it **reopens** (the engine's connectors are fixed at Open): new callers wait on the host gate, readers already handed out finish, the engine is disposed and re-opened on the same path (Open upgrades it). Opens, upgrades and reopens are serialized. `dispose()` (server dispose = lease lost or idle eviction) disposes the engine (which closes the store); a restart opens from storage plus the composed description (R74: no commit when unchanged). `Changed` is raised after every applied upgrade or reopen.
- **S3 Deliveries.** `EnvironmentDeliveries.Current()` = one `DeliveryChannel.Deploy` delivery per app that has a `live` pointer (name = app name, packages = that version's `application.json` packages) plus, when `graphs/loaded-graph.json` exists, one `DeliveryChannel.Promote` delivery (name = record `name`, packages = record `packages`); sorted Deploy-before-Promote, then by name. `loaded-graph.json` stays as the promote record (it is the input of `graph/loaded`); only the instance built from it is retired.
- **S4 Delivery order.** All deploys and promotes of one environment run one at a time under the host's delivery mutex: (1) packages stored immutably (as today), (2) `EnvironmentCatalogComposer.Compose` over the prospective deliveries — pure; an `EnvironmentCatalogError` rejects (deploy: `AppDeployResultDto` `invalid` with the error's message; `graph/load`: InvalidParams with it), nothing persisted beyond the immutable packages; (3) the app `live` pointer / promote record is persisted; (4) `Redeliver()`. A failure in (4) is reported to `IEnvironmentDiagnostics.UpgradeFailed`, marks the host stale (the next request re-runs `Redeliver` before serving) and answers deploy with `failed`, reason `EnvironmentUpgradeFailedReason = 'deployed, but the environment graph could not be upgraded; it is retried on next use'` (graph/load: InternalError). Validating before persisting matters because §4.3 upgrades discard data irreversibly.
- **S5 Runtime scope.** `Final = Finish(And(PolicyEnv, Depth(bypass)))`, combined with `AccessScopeConjunction.And` (deny-wins, M1).
  - `PolicyEnv` = the AND over every live app X of `PolicyScopeCompiler.FromRules(await AccessPolicySetting.Load(appsStorage, X), catalog.Description).Compile(new PrincipalFacts(ctx.Principal), AccessDefault.Allow)` (`Load` already yields `IPolicyRuleSource`s `{ concept, rulesJson }`). No file: X contributes nothing. Values are typed (R117): a JS number meets an Int64 member as a safe integer, a string never matches a numeric member (no diagnostic). `UnknownConcept` diagnostics (a policied concept the description lacks) are reported and left to the Default. `MalformedPolicyError` from `Load`, or any diagnostic with `Code === PolicyDiagnosticCode.MalformedPolicy` in the compiler's `Diagnostics` (R117: fatal for the app): every concept whose home model (`catalog.HomeModels`) is one of X's own package ids gets Rows `False` and Create/Update/Delete `False`, reported once per policy digest (Q8).
  - `bypass` (spec §11.1) = concepts K whose home package (`catalog.HomeModels.get(K)`) is one of exactly one live app X's own packages, delivered by no other delivery (another app's closure or the promote set), and not in `GovernedConceptsFor(ctx)`; empty when the tenant has no security model (DenyAll stays total, as today). `DepthScopeCompiler.Compile(…, { Bypass })` emits no Rows/Writes/field entries for K.
  - System concepts (`todl.system.*`) get no policy and no depth entries; `Finish` writes theirs.
  - `Finish` (runtime only): (a) **share widening** — subjects `{ PrincipalId, Teams: MembershipFor(ctx).teams }`; every non-system Rows entry `E` becomes `Or(E, ShareGrantScope.Widening(s, ShareRight.Read))`, every Update entry `Or(U, Widening(s, ShareRight.Update))`, every Delete entry `Or(D, Widening(s, ShareRight.Delete))` (`Widening` carries the exact `ConceptIs(SystemNames.ShareGrant)` guard, R114, so lookalike concepts cannot forge grants; an external record is widened through its stub's incoming `record` edge, R100); under `Default: Deny` the default is first materialized per described non-system concept with the M1 `Not(ConceptIs K)` rule so the widening reaches entry-less concepts too (parity: today `ShareWideningInstanceFilter` wraps even DenyAll); (b) `Rows[ShareGrant] = ShareGrantScope.GrantRows(s)` — required, not optional: under R66 a scope whose ShareGrant rows are False widens nothing (R114) — and `Writes[ShareGrant]` Create/Update/Delete `False` (only S8/S9/S10 service scopes write grants); (c) for each read-only external binding `b` of `catalog.Identity.ReadOnly()` (`IExternalBinding`), AND `Not(OwnerIs({b.Model}))` into the Create/Update/Delete of `b.Binding.Concept` (the gate decides it on the fetched row's owner, R100/R103; `DataSourceTransaction` would also refuse at Apply with `NotWritable`, R113); (d) AND `Not(Seeded)` into the root `todl.Element` Update and Delete (spec §6: seeded nodes are read-only at runtime).
  - No identity configured: `PolicyEnv` rows, `Default: Allow`, no depth, no widening; (c) and (d) still apply.
  - Cache key (`IGraphScope.Digest`) = JSON of `[ConnectorPrincipalDigest, tenant, claims hash, SchemaVersion, security generation, PolicyDigest]`, where `PolicyDigest` = sha256 over each live app's name and policy text (absent = empty). The policy files are re-read per `ScopeFor` (today they were read per request), so a policy edit applies on the next request. Grants are graph data evaluated by predicate: a share never invalidates the cache.
- **S6 Runtime placement.** `IGraphScope.Placement(modelId?)` at runtime wraps TODL `new EnvironmentNodePlacement(catalog.Identity, catalog.HomeModels)` (`Place(concept, properties): Cypher.INodePlace`): `INodePlace.Defaults` = the placement's own `Defaults` (R112: the String-typed external id member when the write leaves it absent) unioned with the depth create defaults (owner members; the two never share a member); `modelId` does not affect placement. Placement throws `EngineBridgeError` `NoHomeModel` (a concept missing from `HomeModels`), `AmbiguousExternalBinding` (several exact-concept bindings) or `UnsupportedValue` (an external id value that is not a bigint, finite number or non-empty string); S10 maps them. An external create with a numeric id member must give the id value (R112/Q3: a UUID cannot be stored; refused at Apply as `UnsupportedExternalChange`).
- **S7 `application/open`.** Validates the app is live and binds its name to the connection; required by `data/write`, `data/share|unshare|shares/list`, `data/assign` (error unchanged: "no application selected"); not required by `cypher/*`, `connector/*`, `model/*`; no effect on scope or catalog (Q1).
- **S8 Shares as graph data.** The wire `id` of a record is its engine public id (`RecordKey`, `ConceptIdFields` retire). `Share`/`Unshare`/`List` first read the record under the caller's scope (`reader.ConceptOf(id)` must be `params.concept` or a subtype, else `not-found`; an external record has no stored node until a grant links it, so its concept comes from `catalog.Identity.Parse(id).Binding.Binding.Concept` and its visibility needs a fetch — **[O1]**). `CanShare` = `evaluator.Allows(principal, Share, EngineInstanceView)` OR a visible grant on the record for the caller's subjects with `share = true` (grant ids from `ShareGrants.PublicId(record, kind, id)` for the principal and each team). Writes run under `ShareServiceScope.For(callerScope, grantIds)` = the caller scope with `Rows[ShareGrant] = Or(GrantRows(s), IdIn(grantIds))` and `Writes[ShareGrant]` Create/Update/Delete = `IdIn(grantIds)`, so the engine confines the transaction to exactly those grants. Share = create-or-update grant `ShareGrants.PublicId(recordId, kind: ShareSubject, subjectId)` (deterministic, so a re-share is an update; R114) with Owner `SystemPackage.Ref.model` (`'todl.system'`), `ShareGrants.Properties(kind, subjectId, rights)` (every `ShareRight` not listed is false), and a `SystemNames.Record` link (an external record: `LinkOptions.ExternalTarget { Concept: parsed.Binding.Binding.Concept, Owner: parsed.Binding.Model }` from `Identity.Parse`; the engine admits it only when the transaction fetched the row — **[O1]**); `ShareSubject` values equal the protocol's `ShareSubjectKind`; unknown team → `invalid` (`IsKnownTeam`, as today). Unshare = delete that grant; absent → `not-found`. List = grants whose `record` links to the record (scope Rows `Or(GrantRows(s), Related('record', Out, IdIn{record}))`), mapped to `ShareGrantDto { concept: record concept, recordId, subject, rights: true rights in ShareRight order }`. Identity required (error unchanged).
- **S9 Assign.** Same record read and `Allows(Assign)` OR grant `assign = true`; `evaluator.AssignWrites(...)` and its status mapping unchanged; written under `AssignScope.For(callerScope, concept, recordId, ownershipMembers)`: `Writes[concept].Update = IdIn({recordId})` (replacing the caller's Update rule: assign bypasses the Update gate, as today) and `ReadOnlyExact.Update[concept]` = every member of the concept except the ownership members. A `ConflictError` or a `ConnectorError` whose cause is an `ExternalWriteError` with a first failure of kind `conflict` → `denied` "write conflict"; any other failure → `denied` "write failed" (today's reasons). Assigning an external record writes an external node, which needs a same-transaction fetch — **[O1]**.
- **S10 `data/write`.** One engine transaction per batch (Q3). Pre-checks per op, before anything begins: unknown op kind, unknown concept, id required for update/delete, and the existing `RuntimeWritePayloadValidator` reasons (re-based on the engine description; relationship members stay unwritable, as today). A pre-check failure gives that op its status and every other op `failed` + `atomic batch rolled back`. Creates: `Placement.Place` → `CreateNode(PublicId, concept, { Owner })`, `SetProperty` per field, `SetDefault` per placement default. Updates: `SetProperty`. Updates and deletes of an external record need its row fetched in the same transaction (R103) — **[O1]**; on engine nodes they proceed as written. Deletes: first the grants linked to the record (`Links(record, In, SystemNames.Record)` on the transaction), with the batch scope widened by `Writes[ShareGrant].Delete = IdIn(those grant ids)`, then `DeleteNode`. Commit failure → `EngineWriteFailure.Map` (below); the op it attributes (error's public id equals the op's id or placed id) gets the mapped status, the others `failed` + rolled back; unattributed → every op the mapped status. Success → every op `applied`, creates with `id`.
  - **`EngineWriteFailure.Map(error): { Status: AppWriteStatus; Reason: string }`**: `ConflictError` / `CypherWriteErrorCode.Conflict` → `conflict` "write conflict"; `AccessError` `MemberReadOnly` / `HiddenMember` → `denied` "not authorized for a field", other `AccessError` → `denied` "not authorized for this record"; `CommitError` → `invalid` with the `CommitErrorCode` name; an `EngineBridgeError` thrown by placement (S6) — `NoHomeModel`, `AmbiguousExternalBinding`, `UnsupportedValue` → `invalid` with the `EngineBridgeErrorCode` name; a `ConnectorError` with `Phase === ConnectorPhase.Apply` whose `cause` is an `EngineBridgeError` (`ChangeBatcher`, R113): `NotWritable` → `invalid` "binding is read-only", `ForeignId` / `UnsupportedExternalChange` → `invalid` with the code name; a `ConnectorError` (`Phase` `Commit`) whose `cause` is an `ExternalWriteError` with `Code` `ExternalWriteFailed` → by its first `Failures` kind `conflict`→`conflict` "write conflict", `unsupported`→`invalid`, `error`→`failed` (R113); `CompensationFailed` → `failed` "write failed"; any other `ConnectorError` (incl. an adapter error that propagated as the cause, a `Fetch`-phase `ExternalRowInvalid`, a `Prepare` timeout) → `failed` "write failed". Unknown errors propagate (InternalError). A compensation that fails after the caller was answered surfaces only on `GraphEngine.ConnectorRevertFailed` (Task 5 diagnostics).
- **S11 Keyset cursors.** `CypherKeysetPage` replaces offset paging for every engine Cypher page (dev and runtime `cypher/query`, runtime `connector/read*`, runtime `model/view`). Wire cursor = `PageCursorCodec.Encode({ offset: 0, fingerprint: fp + '\u0000' + CypherCursor.Encode() })`, `fp` = `PageFingerprint.Of('cypher', source, canonical params, SchemaVersion, scope Digest[, 'model', modelId])` — the commit is no longer in it, so commits between pages neither repeat nor skip rows (M2.1 D8); a schema upgrade or another principal stales the cursor. The first page runs with `Limits: { Skip: 0, RowCap }` (RowCap alone is the truncating, non-paged mode, R104), later pages with `{ After: CypherCursor.Decode(...), RowCap }` (never both `After` and `Skip`: InvalidArgument); the next cursor from `result.NextCursor` (present exactly when `HasMore` and the order is over returned columns; the cursor's own `Commit` is informational). When `HasMore` holds but `NextCursor` is absent (`ORDER BY` over a non-returned expression), the chain falls back to offset paging: the wire cursor carries the next offset and no Cypher cursor, and the following pages run with `Skip` (Q10). The upgrade-retry loop of `DevCypherQuery` stays but compares `SchemaVersion` only. `GraphDataDigest` and `GraphRevision` fingerprints retire.
- **S12 Runtime `modelId`.** `cypher/query` and `cypher/execute` accept a runtime `modelId` that is one of `catalog.Packages` model ids other than `todl.system`; `cypher/models` lists exactly those (sorted). The scoping is M1's (`Or(ConceptIs todl.Term, OwnerIs({modelId}))` on `todl.Element`, T6-b/T7-b); runtime owners are home packages (engine nodes) and binding models (external nodes), so the filter means "this package's data". `RuntimeModelScopeMessage` retires.

## Review Focus

1. A redeploy drops a package that another app still delivers, or two apps' deploys race: the shared package's data must survive, and the environment must never end up composed from a set nobody validated. → Task 6 tests `package still delivered by another app keeps its data` and `concurrent deploys are serialized and both land`.
2. A principal never calls `application/open` (or opens a permissive app) to dodge a restrictive app policy: the scope must be identical either way. → Task 7 test `binding an app does not change the scope`.
3. A delete of a shared record followed by a create with the same public id: the new record must not inherit the old grants. → Task 10 test `recreated record is not widened by old grants`.
4. The worker loses the tenant lease mid-request, then another worker (or a restart) opens the same LMDB: the second open must succeed after the first host disposes, and see every committed write. → Task 5 tests `lease loss disposes the engine` and `reopen after restart sees committed data`.
5. A commit lands between two pages of a long runtime `cypher/query`: page 2 continues after page 1's last row (no repeat, no skip); a policy-file edit between pages stales the cursor. → Task 4 test `commit between pages neither repeats nor skips`; Task 7 test `policy edit stales the cursor`.
