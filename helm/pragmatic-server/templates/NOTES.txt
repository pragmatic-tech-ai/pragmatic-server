{{- if and (gt (int .Values.replicaCount) 1) (not .Values.redis.url) (not .Values.redis.existingSecret) }}

WARNING: replicaCount is {{ .Values.replicaCount }} but no Redis is configured. replicaCount > 1 is only safe with
redis.url (or redis.existingSecret) set -- the tenant ownership lease stops two replicas from writing one tenant.
Without it, several replicas can open the same tenant's storage at once. Set redis.url, or scale to replicaCount 1.
Route tenants with session affinity (or rely on client retry) when scaling out, since a non-owner replica rejects
with a retryable 503.
{{- end }}
{{- if .Values.clientTls.existingSecret }}

SECURITY: the client-facing CA (clientTls / PRAGMATIC_CLIENT_TLS_CA_FILE) and the worker mTLS CA
(cluster.tls / PRAGMATIC_TLS_CA_FILE) MUST be distinct. If they share a CA, a client that reaches a
worker directly could present a cert that spoofs a machine fingerprint.
{{- end }}

NOTE: multi-replica OIDC login requires redis.url -- the OIDC flow-state store is in-memory and
per-replica otherwise, so a login callback landing on a different replica fails.
{{- if or .Values.secrets.provisioned .Values.secrets.provisionedExistingSecret }}

Per-tenant provisioned secrets are wired: every oidc.clientSecretRef and bootstrap.adminPasswordRef
named in tenants.json must have a matching key in the provisioned Secret (chart-managed
secrets.provisioned, or secrets.provisionedExistingSecret). A tenant naming a ref with no matching
value fails that tenant closed.
A tenant may set bootstrap.allowAdminPasswordRotation: true in tenants.json to re-hash the bootstrap admin
credential when the value behind its adminPasswordRef changes (default: no rotation).
{{- end }}
{{- if .Values.cluster.enabled }}

Cluster mode is enabled: a worker StatefulSet ({{ .Values.cluster.worker.replicas }}) behind a gateway
Deployment ({{ .Values.cluster.gateway.replicas }}). The worker tier REQUIRES Redis -- the ownership lease
keeps one worker per tenant. Set redis.url (or redis.existingSecret); without it two workers could open one

all workers share one server cert whose SAN equals cluster.workerServerName.
