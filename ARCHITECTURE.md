# pragmatic-server — Architecture Index

> Navigational map for orientation. Read this before re-exploring. **Maintenance rule:** when a change moves or renames a seam below, update this file in the same commit. Line numbers drift — treat them as "near here", trust the symbol name.

**Package:** `@pragmatic-tech-ai/pragmatic-server` — Layer **L4** headless server. Exposes the TODL engine (+ connectors + identity) to remote clients over `pragmatic-protocol` (JSON-RPC 2.0 over WebSocket). Consumes TODL + todl-runtime + pragmatic-protocol + todl-identity + todl-platform-node as built `dist` via `file:` sibling deps.

**Vision context (read these memories):** the server is two **tenant types** — a *development* center (collaborative edit of ONE active solution; the surface SP3/Cypher shipped against) and a *runtime* graph provider (compiled application = package set + connectors). See memory `project_server_dual_purpose` and `project_server_architecture`. The dev-vs-runtime tenant **type** now exists in code as `TenantPurpose` (`src/tenancy/tenant-purpose.ts`: `Development` / `Runtime`; `PragmaticServer.Purpose()`); the runtime data-op surface is described under "Runtime data ops" below.

## Layering & composition

- Per-tenant **`PragmaticServer`** builds a `LazyCompositionRoot(HostKinds.Server)` — lazy domain modules (solution-services, language-service: Dormant→Active on first `Resolve`) + eager infra (storage, prompt, package source/store, connectors). `src/pragmatic-server.ts`.
- Engine-never-imports-server holds: the server composes down into TODL; TODL has no server symbol.

## Entry points

- **Programmatic:** `PragmaticServer` (`src/pragmatic-server.ts`) — `Start` / `OpenSolution(dir)` / `Manager()` / `LanguageService()` / `DevEngine()` / `DevScopes()` / `DevCypher()` / `DevModelView()` / `ExecuteCypher(ctx, modelId, request)` / `Connectors()` / `Dispose`.
- **Process:** `bin` entry via `ServerBootstrap` + `ServerConfigLoader` (`src/config/`) — env+file config, fail-closed; SIGTERM graceful shutdown.
- **Host:** `PragmaticServerHost` (`src/host/pragmatic-server-host.ts`) — one server over a `ws` `WebSocketServer({ noServer: true })`; `StartAsync` / `DisposeAsync`. WorkerHost variant for multi-tenant workers.

## HTTP / transport surface (`src/host/pragmatic-server-host.ts`)

- `createServer()`/`httpsCreateServer` + `WebSocketServer` (~:213); upgrades via `wss.handleUpgrade` (~:430). **WebSocket is the primary surface.**
- HTTP router `Request(req,res)` (~:482):
  - `/healthz` + `/readyz` — `HealthEndpoint` (`src/host/health-endpoint.ts`), unauthenticated.
  - `/auth/login`, `/auth/oidc/begin`, `/auth/oidc/callback`, `/auth/machine` — `AuthHttpEndpoint` (`src/host/auth-http-endpoint.ts`), deny-by-default token issuance.
  - `/app/<tenant>/<app>/...` — `AppServingEndpoint` (`src/host/apps/app-serving-endpoint.ts`, `RoutePrefix`), matched before tenant resolution: serves a deployed app's SPA shell and UI bundle same-origin (only the files its manifest lists: `ui.entry`, `ui.assets`; every segment validated; anything else a bare 404). The shell carries the app name only; the tenant comes from the session cookie at WS auth.
  - everything else → 404.

## Domain binding: solution → graph (`src/pragmatic-server.ts`)

- `Manager()` (:202) → `root.Resolve(SolutionManagerService.Key)`. Holds **ONE active solution** (engine side; see TODL index). `OpenSolution` (:212) delegates to the manager.
- The dev tenant's graph is the embedded engine (`DevEngine()`, see "Dev graph engine"); the runtime tenant composes from an application's *package set* (`GraphForPragmaticApp`) or the loaded environment graph.

## Cypher query path (`src/host/cypher/`)

- **Dev `cypher/query` / `cypher/models`** run on the dev graph engine (`EngineCypherQuery`, see "Dev graph engine"); the handler gets it as `IGraphCypherQuery` (its 6th Attach parameter, `devCypher`, from `DevelopmentAttachArgs`). The legacy dev graph caches (`TenantGraphCache`, `ModelShardCache`, `ModelShardGraph`, `TenantGraphComposition`) are gone. The runtime branches (bound app, environment graph) still execute TODL `Cypher.CypherEngine.OverQuery` over an `IGraphQuery`.
- **Read endpoint guards:** `cypher/query` parses once and rejects a well-formed write (names `cypher/execute`) and, when paged, a tail SKIP/LIMIT. Runtime cursors also fingerprint the reachable data (`paging/graph-data-digest.ts`), since runtime graphs re-pull per request.
- **Cells:** `cypher-result-mapper.ts` decodes engine cells with `Cypher.CypherCellCodec` (node = `{ "$node": … }`, reserved-key maps escaped as `{ "$map": … }`) — never by shape.
- **Writes (`cypher/execute`, dev):** run on the dev graph engine (`DevCypherExecute`, see "Dev graph engine"). The legacy draft writer (`DevCypherExecutor`, `DevModelWriter`, `AuthorizingCypherWriter`, `dev-write-security.ts`, `DevWriteTargetSource`, `ReflectedView`) is gone; `write-lock.ts` (`IWriteLock`, `InProcessWriteLock`; `RedisWriteLock` from `RedisTenantOwnership` in a cluster, via `PragmaticServerOptions.writeLock`) and `cypher-execute-result-mapper.ts` (`Applied(status, revision, page, engine stats)` / `Refused(status, revision, reason)`, over the graph engine's `CypherWriteStatsDto`) remain. Secured runtime graphs forward `Materialize` (read-your-writes).
- **Push-down (runtime):** a runtime read passes `{ text, parameters }` to `GraphForPragmaticApp`, which pushes `Cypher.CypherPushDown` alone (the query's own WHERE / inline-property equalities, a superset of the rows the query itself can match) into `ConnectorPrefetch` source queries. Tier-2 access is retired: no per-app access-policy file, TODL model policy or app-private concept bypass is read; only the tenant security model decides.
- **Handler:** `ServerConnectionHandler` registers `CypherProtocol.Query`, `CypherProtocol.Models` and `CypherProtocol.Execute` (dev only: `EnsureDevelopment`; `modelId` required) under `guarded` / `guardedNoParams` (rate-limit→authorize→handler); `cypher-param-converter.ts` (wire params→engine, `Object.create(null)` anti-`__proto__`), `cypher-result-mapper.ts` (engine PascalCase→wire camelCase). Error map: syntax/semantic→InvalidParams, `CypherTimeout`→ -32030 (`EngineCypherQuery.TimeoutCode`, re-exported as `ServerConnectionHandler.CypherTimeoutCode`). Limits from `CypherLimits` config.

## Named graphs (`graph/*`, `src/host/graphs/`)

- `ServerConnectionHandler.RegisterGraphHandlers` maps `GraphProtocol` onto two seams: `graph/{create,list,get,delete,contribute,export}` → `IDevGraphService` (`DevGraphService` over `DevGraphStore`; `GraphExistsError` / `GraphNotFoundError` / `GraphNameInvalidError`, codes in `graph-error-codes.ts`; contributed packages ingested by `graph-package-ingest.ts`) and `graph/{load,loaded}` → `IEnvironmentGraphHost` (`PragmaticServer.LoadEnvironmentGraph` promotes through the environment engine's delivery gate, ruling S4: packages stored by `GraphPackageIngest`, then `EnvironmentEngineHost.Deliver(Promote change, persist = PromoteRecordStore.Save)`; an `EnvironmentCatalogError` is InvalidParams with its message and the record is left as it was, an `EnvironmentUpgradeFailedError` is InternalError with `EnvironmentUpgradeFailedError.PromoteReason` (`promoted, but the environment graph could not be upgraded; it is retried on next use`); `LoadedGraph` reads `PromoteRecordStore`. Until Task 8 `cypher/query` on a runtime tenant still reads the legacy `EnvironmentGraph` / `EnvironmentGraphOverlay` of `environment-graph.ts`, rebuilt lazily from the promote record). Both arrive as Attach parameters (`devGraphService` from `DevelopmentAttachArgs`, `environmentGraphHost` from the runtime args); a missing one answers InvalidRequest (`GraphServiceUnavailableMessage` / `EnvironmentGraphHostUnavailableMessage`).

## Dev graph engine (`src/host/engine/`)

Plan M1.4 moves the dev-tenant graph onto an embedded pragmatic-graph engine (`@pragmatic-tech-ai/graph`, `file:../pragmatic-graph`). Inputs come from SAVED `.todl` files only, never the language service's unsaved buffers (`DidChange` text is a live buffer).

- **`SavedMemberReader`** (`saved-member-reader.ts`) - per member: `TodlSourceCollector.Collect(storage)` + `ResolveBasesFor(storage)` -> `SavedMember { Storage, Sources, Bases, OriginOf, Models }`; `Models` = the `model` containers the member's own sources declare (compile provenance). `NamespaceOf(modelId, solutionName)` = id prefix, else solution name. `DeclaredModelCache` keeps each storage's declared models for the source hash they were compiled from, so an unchanged member is not recompiled; the engine host shares ONE reader between the snapshot source and the workspace (both constructors take an optional reader).
- **`DevSnapshotSource.Current()`** (`dev-snapshot-source.ts`) - every member with a model compiled from its saved sources (absolute uris) by TODL `SavedModelCompiler` (one package per model id, so seed `Owner` = model id; instances outside every model -> the solution package), described by TODL `ExternalCatalogDescriber` (ruling S18) with `DefaultConnector` and `LocalConnector` both `TodlNames.FileConnector`, plans `ConnectorPlanEmitter.PlanFor(repository, modelId)` per accepted model (undefined skipped; each plan's `Model` re-keyed from the declaration name to the model id, the seed Owner id), `Deliveries` = each model id -> `[solution name]`. External bindings are emitted on dev now (R118's M1 default ends): `DevSnapshot.Connectors` = the catalog's plans (sorted by name), `Identity` = its `ExternalIdentity`. An `EnvironmentCatalogError` (e.g. DuplicateExternalSource: two models binding one source) fails `Current()`, except that sources with compile errors fail with `DevSnapshotCompileError` instead (compile errors outrank; the class lives in `dev-snapshot-source.ts`, re-exported by the host). The failure is memoized for the saved state that produced it (`FailedSnapshot` keyed by the `SnapshotKey`), so a repeated `Current()` rethrows without recompiling until a save changes that state. Conflicting datasource redeclarations never reach the describer on dev: one compile of the whole solution reports them as compile errors first. `Description.Version` is the content digest `GraphEngine.Upgrade` compares. Base nodes compiled from an in-solution member that is itself compiled here are stripped (`OriginOf` `OpenProject`), so nothing is declared twice. `CompileDiagnostics` carries the compile's diagnostics (an error = the saved sources do not compile).
- **`ServerModelWorkspace`** (`server-model-workspace.ts`) - TODL `ITodlModelWorkspace` for `TodlFileConnector`: `OpenDraft(modelId)` finds the member whose saved sources declare the model (`OwningMember`, the only copy), drafts over its sources (storage-relative uris), `SourceHash` = `TodlSourceCollector.SourceHash`. Solution name / undeclared id -> undefined (not editable). Each `WriteFile`/`DeleteFile` is a per-file compare-and-swap (storage must hold the opening text or this session's own last write, else it refuses with `EngineBridgeError` `Stale` -> the connector fails the commit Stale, restores what it wrote and does not count the refused write as unrestored: two models sharing a file cannot lose an edit), then `DidChange(absoluteUri, text)` / `DidDelete(absoluteUri)` + `WhenIdle()`; before its first write each session checks the installed write fence (`WriteFenceSlot`, ctor's optional fifth parameter; a lost fence, or NO fence installed (fail closed: only a writer holding the tenant lease persists), refuses the write untouched as `Stale`, checked once so a restore is never refused); a write of the exact text the file already holds is a no-op only when a sibling session of the same writer wrote it (the `WriteFenceSlot` remembers, per installed fence, absolute uri -> text every session wrote, cleared on install and dispose; every model drafts over all its member's files, so a delete's dangling-reference removal is emitted by both); identical text from anyone else (an outside save) is never adopted and is refused as `Stale` (N1), and two models deleting one file are refused the same way; a refresh failure goes to `IDevWriteDiagnostics.RefreshFailed` (`LoggerDevWriteDiagnostics` on the server logger, error names only) and never fails the write. TODL's `TodlFileConnector` writes only the files a model's changes touched (a file whose emission equals the session's baseline at open is skipped, so a model never re-formats a file only another model changed). `IDevLanguageService` (`dev-language-service.ts`) is the language-service slice the engine side reads and writes through. Absolute uris: `TodlSourceCollector.AbsoluteUri`.
- `IDevSolution` (`dev-solution.ts`) is the solution slice it reads (`Name`, `Members.ToArray()`); TODL `Solution` satisfies it.
- **Purpose-free engine seam** (`graph-engine-host.ts`, ruling S1): `IGraphEngineHost { Engine(); Snapshot(): Promise<IEngineSnapshot>; Description(); Changed: ISignal<void> }`, `IEngineSnapshot { Description; CellMapper (TODL `EngineCellMapper`); Models; Connectors: IExternalConnectorPlan[]; Identity: ExternalIdentity | undefined }`. The shared engine-side classes (`AccessScopeSource`, `EngineCypherQuery`) depend on this seam only; `DevSnapshot` extends `IEngineSnapshot` (on dev `Connectors` = the external plans the describer emits and `Identity` their `ExternalIdentity`, ruling S18). `ConnectorPrincipalDigest` lives in `principal-digest.ts`.
- **`DevGraphEngineHost`** (`dev-graph-engine-host.ts`) implements `IDevGraphEngine extends IGraphEngineHost { Snapshot(): Promise<DevSnapshot>; WhenUpgraded(); WhenWritesSettled(); InstallWriteFence(fence): IDisposable }` + `IDisposable` (`Snapshot()` = the whole `DevSnapshot` the engine runs in one read, incl. its `CellMapper`: TODL `EngineCellMapper` over the same compiled metadata). `PragmaticServer.DevEngine()` memoizes one (`devEngine ??=`; throws once the server is disposing; `DoDispose` disposes the scope source and then it, after the connectors host and identity flow store, just before draining the language service); `ServerConnectionHandler.DevelopmentAttachArgs` hands it (with `devGraphService`) to every dev-tenant `Attach` in BOTH `PragmaticServerHost` and `WorkerHost` (the handler no longer takes the engine itself: it reaches it only through `devCypher`, `devModelView` and `cypherExecuteProvider`). Diagnostics: `LoggerDevEngineDiagnostics` and `LoggerDevWriteDiagnostics` on the server logger (`options.logger ?? NullLogger`, as the other dev diagnostics; error names only, never `console.error`). Opens on first use: `GraphEngine.Open({ Description, Storage: Memory, Connectors: [TodlFileConnector(ServerModelWorkspace), ...one LazyExternalConnector(plan, services, snapshot.Identity) per DevSnapshot.Connectors entry], PrepareTimeoutMs: DevGraphEngineHost.PrepareTimeoutMs (30000, explicit; a ctor parameter for tests) })`, no solution -> the empty description (ruling S18; external plans without an Identity are an invariant error). `LazyExternalConnector` (`lazy-external-connector.ts`, purpose-free, ruling R21; the runtime host reuses it) takes name, residency and capabilities from a `DataSourceConnector` built over an unopened adapter (which also checks the bindings against the identity) and opens the real one, `DataSourceConnector.Open(plan, catalog, services, identity)` (R3), on its first `Fetch` / `Begin`; a failed open is forgotten and retried by the next call, so an unreachable or misconfigured source fails only the calls touching its bindings, never the engine open, an upgrade or a reopen. The catalog is the `DataSourceAdapterCatalog` the ctor's eighth parameter `services: () => IServiceProvider` resolves (`PragmaticServer` passes `() => root.Services()`); the connector borrows its adapter and never disposes it. The reader, `DevSnapshotSource` and workspace are kept per language service across opens (`SnapshotParts`), so a failed open does not recompile until a save. `LazyExternalConnector.Reset()` (ruling R23) forgets the opened connector so the next use re-opens it, for a refresh after the catalog disposed its adapters. Reopen (ruling S2's rule on dev): a pass whose `ConnectorSetKey.Of(snapshot.Connectors, snapshot.Identity)` (`connector-set-key.ts`: canonical JSON of each plan's Name, Spec and Bindings plus every field-mapped member as the identity resolves it; wider than S2's Name+Spec because a `DataSourceConnector` captures bindings and member shapes at construction) differs from the running engine's reopens instead of upgrading: new callers wait on the host gate (`reopening`), a fresh memory engine is launched from the new snapshot (dev data lives in the `.todl` files, so its seed carries everything over) and swapped in, the retired engine is disposed after `RetireGraceMs` (= `MaxSettleMs`, on the settle timer seam; or at teardown) so readers already handed out finish; its committed-but-unfinalized file transactions are abandoned per connector (`EngineWriteTracker.Abandon(connector)`). The drain's settle wait precedes a reopen exactly as an upgrade. A teardown that begins while a reopen launches disposes the launched engine instead of swapping it in, and an engine retired after teardown collected the retired set is disposed at once. An `EnvironmentCatalogError` at open or in a pass is `DevSnapshotCatalogFailure`: every `Engine()` / `Snapshot()` / `Description()` rejects with `ResponseError(InvalidRequest, message)` until a later pass describes (applied, or equal to the running version); reported as `IDevEngineDiagnostics.CatalogFailed`. Sources that do not compile keep the previous rule (the previous version is kept, `UpgradeFailed`) and never enter the catalog-failure state. A retired engine that fails to close is `RetireFailed`. Upgrade: `GraphChanged` only (re)arms a `UpgradeDebounceMs = 150` debounce (`IUpgradeTimer`; never works inside the language-service queue or a commit's refresh); one drain loop then recompiles (`DevSnapshotSource.Current()`) and calls `engine.Upgrade` only when `Version` differs, changes arriving meanwhile coalescing into one more pass. The connector is wrapped by `EngineWriteTracker`, which counts the engine's own connector transactions (Begin -> the engine's `CommitApplied` after Finalize (M1: a connector Commit alone does not settle; the host subscribes `CommitApplied` and calls `Finalized(commit)`, which ends only the transactions whose change keys appear in that Batch commit's ops (a synthetic DETACH unlink matches a DeleteNode of either end), so an upgrade or its seed commit never ends one early (N3); `Abandon()` on dispose), a failed Commit, or Revert, plus a post-commit compensating Revert); `WhenWritesSettled()` is its `Settled()`. Every settle wait is bounded (ruling F-f) by `DevGraphEngineHost.MaxSettleMs` = 2 x `PrepareTimeoutMs` through an injected timer seam (`BoundedWait`, ctor's seventh parameter): the upgrade drain reports `IDevEngineDiagnostics.WritesUnsettled` and re-arms (`pending`), so the skipped upgrade runs as soon as the writes settle without waiting for another `GraphChanged`; teardown bounds its wait on the drain too (a hang in `Source.Current()` or `engine.Upgrade`: `DrainUnsettled`), then on the writes and on the engine dispose, reporting each and disposing anyway, so dispose never hangs. `IsOpen` (`@internal`, true only after a successful open) exists for the worker-host test alone: the drain waits until none is in flight and re-reads when one began while it read, so a multi-file commit half on disk is never applied (an upgrade mid-commit would also fail that commit, ruling R77); the one remaining window is a commit that begins while `Upgrade` runs, which fails with a retry-safe ConflictError. `DevSnapshotSource` returns its previous snapshot without recompiling when the solution, every member's source hash and its bases fingerprint (`SavedMember.BasesHash`: content of the resolved bases + origins, so freshly rebuilt sibling bases still match) are unchanged; `DeclaredModelCache` never caches a compile with errors. A throwing `Changed` subscriber is reported (`ChangedHandlerFailed`) and never stalls later upgrades. A throw or compile error (`DevSnapshotCompileError`) is reported to `IDevEngineDiagnostics` and not applied: the engine keeps its previous version, the next change retries. `Changed` is raised after each applied upgrade or reopen. `WhenUpgraded()` resolves once every upgrade already asked for has finished: a pending debounce is cut short (its drain pass runs now) and the running drain is awaited; `DevCypherExecute` calls it after a commit (the commit's file writes raised `GraphChanged` before each `WhenIdle` it awaited). There is no forced re-read (the legacy writer's `Synchronize()` is gone with it). The ctor's optional fifth parameter is the workspace's `IDevWriteDiagnostics`.

## Runtime data ops (`TenantPurpose.Runtime`; `src/host/sharing/`, `src/host/apps/`)

- **Applications:** `PragmaticAppsRegistry` (`src/host/apps/`) lists/opens an application (manifest = package set; `LiveApplications()` = only the apps whose `live` pointer names a version with a manifest, the environment deliveries); a connection binds one app (`boundApp`) via `application/open`. Data ops require a bound app, else "no application selected".
- **Per-app `PragmaticServer` methods** (Runtime only): `GraphForPragmaticApp`, `WriteForPragmaticApp` (`data/write`), `ShareForPragmaticApp` / `UnshareForPragmaticApp` / `ListSharesForPragmaticApp` (`data/share`, `data/unshare`, `data/shares/list`; SP-5 record sharing), `AssignForPragmaticApp` (`data/assign`; SP-5b record assign). `AppShareStore(name)` is the per-app share persistence.
- **Services** (`src/host/sharing/`): `ShareService` (grant/revoke/list), `ShareStore` + `ShareGrantIndex` (per-principal grants keyed by concept/record; `AllowsRecord`), `AssignService` (changes owner / owning-BU columns under the **Assign** right via role OR record share, bypassing the Update gate; maps `AssignOutcome` from the identity engine to `AssignStatus`; empty mapped fields -> `Invalid`, adapter fault -> `Denied` "write failed", key conflict -> `Denied` "write conflict"), plus `ShareWidening*` filters/authorizers that widen read/write for shared records.
- **Provider threading:** `ServerConnectionHandler.RuntimeAttachArgs(server)` returns `{ applications, appGraphProvider, appWriteProvider, shareProvider, unshareProvider, listSharesProvider, assignProvider }` (all `undefined` for a Development server); both Attach sites (`PragmaticServerHost` and `WorkerHost`) spread it into `ServerConnectionHandler.Attach`, which stores each provider and forwards the call with the bound app name.
- **Policy:** `PolicyGate` maps `data/write`, `data/share`, `data/unshare`, `data/assign` to `writeTenant` (Write/Tenant); the finer Assign/Share rights are enforced inside the services, not the gate.

## Identity / RBAC / authorization

- **`PolicyGate`** — deny-by-default `BuildTable` mapping protocol method → required `{ Action, ResourceKind }` (e.g. `CypherProtocol.Query.method → Read/Tenant` from `Tenant.Id`). `src/host/policy-gate.ts`.
- RBAC instance filtering uses `AccessContext` (from todl-identity) per request, and only the tenant security model (tier 1) decides: per-app `access-policy.json`, TODL model `policy` declarations and app-private concept governance (tier 2) are retired and never read, so a concept the security model does not govern is denied (read and write) like any other. Dev tenants: access depth and field security are compiled into the engine's `AccessScope` (`AccessScopeSource`) and enforced INSIDE the embedded graph engine (reads, writes at commit, model/view). Runtime tenants: the depth filter (widened by record shares) and the field mask are applied in the runtime app graph (`FilteredGraphQuery` + `FieldMaskedGraphQuery`), outside any engine; the write instance gate (`AccessDepthWriteInstanceGate`) is write depth alone; the runtime `model/view` (`ModelReadFilter`) keeps untyped nodes and the instances the access-depth read filter keeps (`InstanceFilterNodeGate` over `PragmaticServer.DepthFilterSource().ReadFilterFor(ctx)`, the handler's trailing Attach parameter `readFilters`; allow-all without identity) and applies the field-read mask, and runtime `model/resources` of an instance that filter hides is `[]`. TODL model `policy` declarations play no part.
- `guarded(...)` pipeline in `ServerConnectionHandler` wraps every method: rate-limit → authorize (PolicyGate) → handler.
