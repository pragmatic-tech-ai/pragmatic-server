# pragmatic-server — Architecture Index

> Navigational map for orientation. Read this before re-exploring. **Maintenance rule:** when a change moves or renames a seam below, update this file in the same commit. Line numbers drift — treat them as "near here", trust the symbol name.

**Package:** `@pragmatic-tech-ai/pragmatic-server` — Layer **L4** headless server. Exposes the TODL engine (+ connectors + identity) to remote clients over `pragmatic-protocol` (JSON-RPC 2.0 over WebSocket). Consumes TODL + todl-runtime + pragmatic-protocol + todl-identity + todl-platform-node as built `dist` via `file:` sibling deps.

**Vision context (read these memories):** the server is two **tenant types** — a *development* center (collaborative edit of ONE active solution; the surface SP3/Cypher shipped against) and a *runtime* graph provider (compiled application = package set + connectors). See memory `project_server_dual_purpose` and `project_server_architecture`. The dev-vs-runtime tenant **type** now exists in code as `TenantPurpose` (`src/tenancy/tenant-purpose.ts`: `Development` / `Runtime`; `PragmaticServer.Purpose()`); the runtime data-op surface is described under "Runtime data ops" below.

## Layering & composition

- Per-tenant **`PragmaticServer`** builds a `LazyCompositionRoot(HostKinds.Server)` — lazy domain modules (solution-services, language-service: Dormant→Active on first `Resolve`) + eager infra (storage, prompt, package source/store, connectors). `src/pragmatic-server.ts`.
- Engine-never-imports-server holds: the server composes down into TODL; TODL has no server symbol.

## Entry points

- **Programmatic:** `PragmaticServer` (`src/pragmatic-server.ts`) — `Start` / `OpenSolution(dir)` / `Manager()` / `LanguageService()` / `DevEngine()` / `DevScopes()` / `DevCypher()` / `DevModelView()` / `DevExecute()` / `DevConnectors()` / `Dispose`; runtime: `EnvironmentEngine()` / `EnvironmentScopes()` / `EnvironmentCypher()` / `EnvironmentExecute()` / `EnvironmentConnectors()` / `EnvironmentModelView()` / `DataChanges()`.

- **Host:** `PragmaticServerHost` (`src/host/pragmatic-server-host.ts`) — one server over a `ws` `WebSocketServer({ noServer: true })`; `StartAsync` / `DisposeAsync`. WorkerHost variant for multi-tenant workers.

## Cypher query path

Source: `src/host/cypher/`.

- **`cypher/query` / `cypher/models`, both purposes (ruling S1)** run on the tenant's graph engine through the one `EngineCypherQuery` (see "Dev graph engine"): dev `PragmaticServer.DevCypher()` over the dev engine and scopes, runtime `PragmaticServer.EnvironmentCypher()` over `EnvironmentEngine()` and `EnvironmentScopes()`. The handler gets it as `IGraphCypherQuery` (its 6th Attach parameter, `cypherQuery`, from `RuntimeAttachArgs` / `DevelopmentAttachArgs`; hosts pass `runtime.cypherQuery ?? development.cypherQuery`) and has no purpose branch. The legacy dev graph caches and the legacy runtime read path (the per-connection app graph, `EnvironmentGraph` / `EnvironmentGraphOverlay` / `NoEnvironmentGraphError` of `graphs/environment-graph.ts`, `paging/graph-data-digest.ts`, the runtime push-down and `FieldMaskedGraphQuery`) are gone.
- **Model filters and shares (ruling R58, M2.3 Task 14 review):** both model filters (`ModelScopes.For`, S12; `ModelScopes.ForOwner`, R53) exempt `ConceptIs(todl.system.ShareGrant)`: a grant is owned by `todl.system` and a Related target is judged under the same scope (R66), so an `OwnerIs` arm alone hid the caller's grants and every record shared to the caller vanished from model-scoped `cypher/query`, `connector/read*` and `model/view`. Grant nodes stay governed by the caller scope's `GrantRows` (its own grants only). **Declared behaviour:** a model-scoped `cypher/query` / `connector/read*` can return the caller's own grant nodes (as it returns taxonomy terms); runtime `model/view` leaves them out.
- **One Cypher (ruling S19):** the server imports the engine's `Cypher` namespace (`@pragmatic-tech-ai/graph`) only, and TODL's `CypherWire` (root export) for the mapped wire DTO and its cell codec; nothing from TODL's own Cypher or `@pragmatic-tech-ai/todl/graph-api`.
- **Read endpoint guards:** `cypher/query` parses once with the engine `Cypher.CypherParser` (`RefuseInvalidReadQuery`: `HasWrites`, the final projection's Skip/Limit) and rejects a well-formed write (names `cypher/execute`) and, when paged, a tail SKIP/LIMIT. Runtime cursors are the engine's keyset cursors (`CypherKeysetPage`, ruling S11): a commit between pages neither repeats nor skips rows; a schema upgrade, a security-setting edit or another principal stales the cursor.
- **Paging fallback (Q10):** a query ordered by an expression that is no returned column gets no engine keyset cursor; its chain pages by offset (`Skip`), so a commit between its pages may repeat or skip rows (the behaviour of every query before M2.3). See "Declared behaviour changes (M2.3)".
- **Cells:** `cypher-result-mapper.ts` decodes the mapped cells (`CypherWire.CypherResultDto`, after `EngineCellMapper.MapResult`) with `CypherWire.CypherCellCodec` (node = `{ "$node": … }`, reserved-key maps escaped as `{ "$map": … }`) — never by shape.
- **Writes (`cypher/execute`):** dev on the dev graph engine (`DevCypherExecute`, see "Dev graph engine"), runtime on the environment engine (`EnvironmentCypherExecute`, see "Runtime environment engine"); both implement `IGraphCypherExecute.Run(ctx, modelId | undefined, ICypherExecuteRequest)` (`graph-cypher-execute.ts`, with the shared `ExecuteAttempt` outcome and `IExecuteDiagnostics` / `LoggerExecuteDiagnostics`) and share placement (`IGraphScope.Placement`), the model write confinement (`ModelWriteScopes`, `model-write-scopes.ts`) and the failure table (`EngineWriteFailure`). The legacy draft writer (`DevCypherExecutor`, `DevModelWriter`, `AuthorizingCypherWriter`, `dev-write-security.ts`, `DevWriteTargetSource`, `ReflectedView`) is gone; `write-lock.ts` (`IWriteLock`, `InProcessWriteLock`; `RedisWriteLock` from `RedisTenantOwnership` in a cluster, via `PragmaticServerOptions.writeLock`) and `cypher-execute-result-mapper.ts` (`Applied(status, revision, page, engine stats)` / `Refused(status, revision, reason)`, over the graph engine's `CypherWriteStatsDto`) remain.
- **Push-down (runtime):** external reads go through the environment engine's `DataSourceConnector`s (advisory push-down, `FetchTranslator`); nothing is pushed by the server. Tier-2 access is retired: no per-app access-policy file, TODL model policy or app-private concept bypass is read; only the tenant security model decides.
- **Handler:** `ServerConnectionHandler` registers `CypherProtocol.Query`, `CypherProtocol.Models` and `CypherProtocol.Execute` (both purposes, gate `writeTenant` (Q9); `modelId` required on dev by `DevCypherExecute`, optional on runtime) under `guarded` / `guardedNoParams` (rate-limit→authorize→handler); `cypher-param-converter.ts` (wire params→engine `Cypher.ParameterValue`, `Object.create(null)` anti-`__proto__`), `cypher-result-mapper.ts` (engine PascalCase→wire camelCase). Error map: syntax/semantic→InvalidParams, `CypherTimeout`→ -32030 (`EngineCypherQuery.TimeoutCode`, re-exported as `ServerConnectionHandler.CypherTimeoutCode`). Limits from `CypherLimits` config.

## Named graphs

The `graph/*` methods; source: `src/host/graphs/`.

- `ServerConnectionHandler.RegisterGraphHandlers` maps `GraphProtocol` onto two seams: `graph/{create,list,get,delete,contribute,export}` → `IDevGraphService` (`DevGraphService` over `DevGraphStore`; `GraphExistsError` / `GraphNotFoundError` / `GraphNameInvalidError`, codes in `graph-error-codes.ts`; contributed packages ingested by `graph-package-ingest.ts`) and `graph/{load,loaded}` → `IEnvironmentGraphHost` (`PragmaticServer.LoadEnvironmentGraph` promotes through the environment engine's delivery gate, ruling S4: packages stored by `GraphPackageIngest`, then `EnvironmentEngineHost.Deliver(Promote change, persist = PromoteRecordStore.Save)`; an `EnvironmentCatalogError` is InvalidParams with its message and the record is left as it was, an `EnvironmentUpgradeFailedError` is InternalError with `EnvironmentUpgradeFailedError.PromoteReason` (`promoted, but the environment graph could not be upgraded; it is retried on next use`); `LoadedGraph` reads `PromoteRecordStore`. `IEnvironmentGraphHost` (`LoadEnvironmentGraph` / `LoadedGraph`) lives in `environment-engine-host.ts`; the promote record is only the input of the Promote delivery: runtime reads are the environment engine's). ## Dev graph engine

Source: `src/host/engine/`.

Plan M1.4 moves the dev-tenant graph onto an embedded pragmatic-graph engine (`@pragmatic-tech-ai/graph`, `file:../pragmatic-graph`). Inputs come from SAVED `.todl` files only, never the language service's unsaved buffers (`DidChange` text is a live buffer).

- **`SavedMemberReader`** (`saved-member-reader.ts`) - per member: `TodlSourceCollector.Collect(storage)` + `ResolveBasesFor(storage)` -> `SavedMember { Storage, Sources, Bases, OriginOf, Models }`; `Models` = the `model` containers the member's own sources declare (compile provenance). `NamespaceOf(modelId, solutionName)` = id prefix, else solution name. `DeclaredModelCache` keeps each storage's declared models for the source hash they were compiled from, so an unchanged member is not recompiled; the engine host shares ONE reader between the snapshot source and the workspace (both constructors take an optional reader).
- **`DevSnapshotSource.Current()`** (`dev-snapshot-source.ts`) - every member with a model compiled from its saved sources (absolute uris) by TODL `SavedModelCompiler` (one package per model id, so seed `Owner` = model id; instances outside every model -> the solution package), described by TODL `ExternalCatalogDescriber` (ruling S18) with `DefaultConnector` and `LocalConnector` both `TodlNames.FileConnector`, plans `ConnectorPlanEmitter.PlanFor(repository, modelId)` per accepted model (undefined skipped; each plan's `Model` re-keyed from the declaration name to the model id, the seed Owner id), `Deliveries` = each model id -> `[solution name]`. External bindings are emitted on dev now (R118's M1 default ends): `DevSnapshot.Connectors` = the catalog's plans (sorted by name), `Identity` = its `ExternalIdentity`. An `EnvironmentCatalogError` (e.g. DuplicateExternalSource: two models binding one source) fails `Current()`, except that sources with compile errors fail with `DevSnapshotCompileError` instead (compile errors outrank; the class lives in `dev-snapshot-source.ts`, re-exported by the host). The failure is memoized for the saved state that produced it (`FailedSnapshot` keyed by the `SnapshotKey`), so a repeated `Current()` rethrows without recompiling until a save changes that state. Conflicting datasource redeclarations never reach the describer on dev: one compile of the whole solution reports them as compile errors first. `Description.Version` is the content digest `GraphEngine.Upgrade` compares. Base nodes compiled from an in-solution member that is itself compiled here are stripped (`OriginOf` `OpenProject`), so nothing is declared twice. `CompileDiagnostics` carries the compile's diagnostics (an error = the saved sources do not compile).
- **`ServerModelWorkspace`** (`server-model-workspace.ts`) - TODL `ITodlModelWorkspace` for `TodlFileConnector`: `OpenDraft(modelId)` finds the member whose saved sources declare the model (`OwningMember`, the only copy), drafts over its sources (storage-relative uris), `SourceHash` = `TodlSourceCollector.SourceHash`. Solution name / undeclared id -> undefined (not editable). Each `WriteFile`/`DeleteFile` is a per-file compare-and-swap (storage must hold the opening text or this session's own last write, else it refuses with `EngineBridgeError` `Stale` -> the connector fails the commit Stale, restores what it wrote and does not count the refused write as unrestored: two models sharing a file cannot lose an edit), then `DidChange(absoluteUri, text)` / `DidDelete(absoluteUri)` + `WhenIdle()`; before its first write each session checks the installed write fence (`WriteFenceSlot`, ctor's optional fifth parameter; a lost fence, or NO fence installed (fail closed: only a writer holding the tenant lease persists), refuses the write untouched as `Stale`, checked once so a restore is never refused); a write of the exact text the file already holds is a no-op only when a sibling session of the same writer wrote it (the `WriteFenceSlot` remembers, per installed fence, absolute uri -> text every session wrote, cleared on install and dispose; every model drafts over all its member's files, so a delete's dangling-reference removal is emitted by both); identical text from anyone else (an outside save) is never adopted and is refused as `Stale` (N1), and two models deleting one file are refused the same way; a refresh failure goes to `IDevWriteDiagnostics.RefreshFailed` (`LoggerDevWriteDiagnostics` on the server logger, error names only) and never fails the write. TODL's `TodlFileConnector` writes only the files a model's changes touched (a file whose emission equals the session's baseline at open is skipped, so a model never re-formats a file only another model changed). `IDevLanguageService` (`dev-language-service.ts`) is the language-service slice the engine side reads and writes through. Absolute uris: `TodlSourceCollector.AbsoluteUri`.
- `IDevSolution` (`dev-solution.ts`) is the solution slice it reads (`Name`, `Members.ToArray()`); TODL `Solution` satisfies it.
- **Purpose-free engine seam** (`graph-engine-host.ts`, ruling S1): `IGraphEngineHost { Engine(); Snapshot(): Promise<IEngineSnapshot>; Description(); ResetConnectors(); Changed: ISignal<void> }` (`ResetConnectors`, R23: forget the running engine's opened external connectors after `connector/refresh`), `IEngineSnapshot { Description; CellMapper (TODL `EngineCellMapper`); Models; Connectors: IExternalConnectorPlan[]; Identity: ExternalIdentity | undefined }`. The shared engine-side classes (`AccessScopeSource`, `EngineCypherQuery`, `EngineConnectorService`) depend on this seam only; `DevSnapshot` extends `IEngineSnapshot` (on dev `Connectors` = the external plans the describer emits and `Identity` their `ExternalIdentity`, ruling S18). `ConnectorPrincipalDigest` lives in `principal-digest.ts`.
- **`DevGraphEngineHost`** (`dev-graph-engine-host.ts`) implements `IDevGraphEngine extends IGraphEngineHost { Snapshot(): Promise<DevSnapshot>; WhenUpgraded(); WhenWritesSettled(); InstallWriteFence(fence): IDisposable }` + `IDisposable` (`Snapshot()` = the whole `DevSnapshot` the engine runs in one read, incl. its `CellMapper`: TODL `EngineCellMapper` over the same compiled metadata).
  - `PragmaticServer.DevEngine()` memoizes one (`devEngine ??=`; throws once the server is disposing; `DoDispose` disposes the scope source and then it, after the connectors host and identity flow store, just before draining the language service); `ServerConnectionHandler.DevelopmentAttachArgs` hands it (with `devGraphService`) to every dev-tenant `Attach` in BOTH `PragmaticServerHost` and `WorkerHost` (the handler no longer takes the engine itself: it reaches it only through `cypherQuery`, `modelView` and `cypherExecute`).
  - Diagnostics: `LoggerDevEngineDiagnostics` and `LoggerDevWriteDiagnostics` on the server logger (`options.logger ?? NullLogger`, as the other dev diagnostics; error names only, never `console.error`).
  - Opens on first use: `GraphEngine.Open({ Description, Storage: Memory, Connectors: [TodlFileConnector(ServerModelWorkspace), ...one LazyExternalConnector(plan, services, snapshot.Identity) per DevSnapshot.Connectors entry], PrepareTimeoutMs: DevGraphEngineHost.PrepareTimeoutMs (30000, explicit; a ctor parameter for tests) })`, no solution -> the empty description (ruling S18; external plans without an Identity are an invariant error).
  - `LazyExternalConnector` (`lazy-external-connector.ts`, purpose-free, ruling R21; the runtime host reuses it) takes name, residency and capabilities from a `DataSourceConnector` built over an unopened adapter (which also checks the bindings against the identity) and opens the real one, `DataSourceConnector.Open(plan, catalog, services, identity)` (R3), on its first `Fetch` / `Begin`; a failed open is forgotten and retried by the next call, so an unreachable or misconfigured source fails only the calls touching its bindings, never the engine open, an upgrade or a reopen.
  - The catalog is the `DataSourceAdapterCatalog` the ctor's eighth parameter `services: () => IServiceProvider` resolves (`PragmaticServer` passes `() => root.Services()`); the connector borrows its adapter and never disposes it.
  - The reader, `DevSnapshotSource` and workspace are kept per language service across opens (`SnapshotParts`), so a failed open does not recompile until a save.
  - `LazyExternalConnector.Reset()` (ruling R23) forgets the opened connector so the next use re-opens it, for a refresh after the catalog disposed its adapters.
  - Reopen (ruling S2's rule on dev): a pass whose `ConnectorSetKey.Of(snapshot.Connectors, snapshot.Identity)` (`connector-set-key.ts`: canonical JSON of each plan's Name, Spec and Bindings plus every field-mapped member as the identity resolves it; wider than S2's Name+Spec because a `DataSourceConnector` captures bindings and member shapes at construction) differs from the running engine's reopens instead of upgrading: new callers wait on the host gate (`reopening`), a fresh memory engine is launched from the new snapshot (dev data lives in the `.todl` files, so its seed carries everything over) and swapped in, the retired engine is disposed after `RetireGraceMs` (= `MaxSettleMs`, on the settle timer seam; or at teardown) so readers already handed out finish; its committed-but-unfinalized file transactions are abandoned per connector (`EngineWriteTracker.Abandon(connector)`).
  - The drain's settle wait precedes a reopen exactly as an upgrade.
  - A teardown that begins while a reopen launches disposes the launched engine instead of swapping it in, and an engine retired after teardown collected the retired set is disposed at once.
  - An `EnvironmentCatalogError` at open or in a pass is `DevSnapshotCatalogFailure`: every `Engine()` / `Snapshot()` / `Description()` rejects with `ResponseError(InvalidRequest, message)` until a later pass describes (applied, or equal to the running version); reported as `IDevEngineDiagnostics.CatalogFailed`.
  - Sources that do not compile keep the previous rule (the previous version is kept, `UpgradeFailed`) and never enter the catalog-failure state.
  - A retired engine that fails to close is `RetireFailed`.
  - Upgrade: `GraphChanged` only (re)arms a `UpgradeDebounceMs = 150` debounce (`IUpgradeTimer`; never works inside the language-service queue or a commit's refresh); one drain loop then recompiles (`DevSnapshotSource.Current()`) and calls `engine.Upgrade` only when `Version` differs, changes arriving meanwhile coalescing into one more pass.
  - The connector is wrapped by `EngineWriteTracker`, which counts the engine's own connector transactions (Begin -> the engine's `CommitApplied` after Finalize (M1: a connector Commit alone does not settle; the host subscribes `CommitApplied` and calls `Finalized(commit)`, which ends only the transactions whose change keys appear in that Batch commit's ops (a synthetic DETACH unlink matches a DeleteNode of either end), so an upgrade or its seed commit never ends one early (N3); `Abandon()` on dispose), a failed Commit, or Revert, plus a post-commit compensating Revert); `WhenWritesSettled()` is its `Settled()`.
  - Every settle wait is bounded (ruling F-f) by `DevGraphEngineHost.MaxSettleMs` = 2 x `PrepareTimeoutMs` through an injected timer seam (`BoundedWait`, ctor's seventh parameter): the upgrade drain reports `IDevEngineDiagnostics.WritesUnsettled` and re-arms (`pending`), so the skipped upgrade runs as soon as the writes settle without waiting for another `GraphChanged`; teardown bounds its wait on the drain too (a hang in `Source.Current()` or `engine.Upgrade`: `DrainUnsettled`), then on the writes and on the engine dispose, reporting each and disposing anyway, so dispose never hangs.
  - `IsOpen` (`@internal`, true only after a successful open) exists for the worker-host test alone: the drain waits until none is in flight and re-reads when one began while it read, so a multi-file commit half on disk is never applied (an upgrade mid-commit would also fail that commit, ruling R77); the one remaining window is a commit that begins while `Upgrade` runs, which fails with a retry-safe ConflictError.
  - `DevSnapshotSource` returns its previous snapshot without recompiling when the solution, every member's source hash and its bases fingerprint (`SavedMember.BasesHash`: content of the resolved bases + origins, so freshly rebuilt sibling bases still match) are unchanged; `DeclaredModelCache` never caches a compile with errors.
  - A throwing `Changed` subscriber is reported (`ChangedHandlerFailed`) and never stalls later upgrades.
  - A throw or compile error (`DevSnapshotCompileError`) is reported to `IDevEngineDiagnostics` and not applied: the engine keeps its previous version, the next change retries.
  - `Changed` is raised after each applied upgrade or reopen.
  - `WhenUpgraded()` resolves once every upgrade already asked for has finished: a pending debounce is cut short (its drain pass runs now) and the running drain is awaited; `DevCypherExecute` calls it after a commit (the commit's file writes raised `GraphChanged` before each `WhenIdle` it awaited).
  - There is no forced re-read (the legacy writer's `Synchronize()` is gone with it).
  - The ctor's optional fifth parameter is the workspace's `IDevWriteDiagnostics`.
- **`AccessScopeSource`** (`access-scope-source.ts`, purpose-free, ruling S1) - the ONE place graph access is decided: `AccessScopeSource(host: IGraphEngineHost, rules: IScopeRules, diagnostics?)` (amendment A2, ruling R13: it holds no identity state), `ScopeFor(ctx): Promise<IGraphScope { Scope: AccessScope; Connector: ConnectorContext (PR12, the caller's: `CallerConnectorContext.For(ctx.Principal)`); Placement(modelId?); Digest }>` (`IGraphScopeSource { ScopeFor; Dropped }`); endpoints pass `Scope` to the engine and never filter or mask themselves. What differs per purpose is the `IScopeRules extends IDisposable { Prepare(schema: ScopeSchema { Engine; Description; Version; Catalog: EngineSchemaCatalog }): Promise<IPreparedRules>; Changed }` strategy (owned and disposed by the source), prepared on every `ScopeFor` against the settled schema: `IPreparedRules { Records(ctx): Promise<IScopeRecords { Scope; Diagnostics: string[]; Principal: PrincipalFacts }>; Finish(scope, ctx); Placement(principal, modelId); Digest }`. Final = `Finish(Records(ctx).Scope)`; the source composes no policy or depth itself, and placement stamps creates from the record part's `PrincipalFacts`. **`DevScopeRules`** (`dev-scope-rules.ts`, `DevScopeRules(solutionName)`; spec §5.1, program ruling PR13): authoring data is governed by the identity RBAC at the `PolicyGate` only, so `Records` = `AccessScope.Build({ Default: Allow })` for every principal the gate admits, with or without identity (the environment security setting is never read on dev; a Development tenant refuses one), and nothing is stamped. `Prepare` returns per the active solution name; `Finish` = identity; `Placement` = `TodlNodePlacement(modelId, NamespaceOf(modelId, solution))` (a missing `modelId` is `GraphError` InvalidArgument); `Digest` = `''` (constant: every gate-passing principal gets the same scope); `Changed` never fires (the source drops its scopes on the host's `Changed`). The model confinement of a model-scoped read or write (`OwnerIs(modelId)`) is applied by its endpoint, unchanged. `AccessScopeConjunction` (same-key Rows ANDed, Writes ANDed per op — `[Create, Update, Delete, Append, AppendTo]`, PR3 — Hidden / HiddenExact and ReadOnly / ReadOnlyExact (per op) unioned key by key, `Endpoints` unioned (PR4; a conflicting pair for one concept throws), a Deny default the other scope's entries would override materialized as `Not(ConceptIs concept)` ANDed onto that concept, never a plain False that would reach its subconcepts) now only confines a caller's scope to a model (`EngineCypherQuery` rows, `DevCypherExecute` writes). Cached per `Digest` = JSON of (`ConnectorPrincipalDigest`, tenant, sha256 of the sorted claims, engine `SchemaVersion`, prepared rules' `Digest` (dev: `''`; runtime: the security setting generation)), an LRU of at most `AccessScopeSource.MaxScopes` (64) compiled scopes; host `Changed` and rules `Changed` drop it (the runtime rules raise `Changed` when the environment security setting is invalidated or on the host's `Changed`; dev rules never raise it). Every compiled scope is opened once on the engine (`BeginRead`, its ScopeValidator) before it is handed out; record diagnostics go to `IScopeDiagnostics` (default `LoggerScopeDiagnostics` over `ILogger`; once per message until the cache drops). Digest coverage: the exact member sets are derived only from the evaluator (tenant + security generation), the principal (principal digest + claims hash) and the schema version, all already in the Digest. Failures are `AccessScopeError` (`AccessScopeErrorCode`).

## Platform security (tier 1)

The server half of the platform security design (`docs/superpowers/specs/2026-11-11-platform-security-architecture-design.md`, implemented S1 to S4). This section is the map; the mechanics are in the bullets under "Runtime environment engine", "Connectors" and "Identity / RBAC / authorization".

- **Two gates, one decision each.** The identity RBAC at the `PolicyGate` (coarse tenant roles: Viewer / Editor / Admin / Owner) decides which endpoints a principal may call, on both purposes. On a Runtime environment, tier 1 then decides which records and fields it sees or writes. A test user needs both a coarse grant and a tier-1 role. Dev authoring data has only the gate (PR13: `DevScopeRules` is allow-all).
- **The setting (layer 2, contract C5).** `EnvironmentSecuritySetting` (`src/host/environment/environment-security-setting.ts`, via `PragmaticServer.SecuritySetting()`) holds the stored `ISecurityModelConfig` (business units, user placements, teams with IdP-group links and manual rows, role and profile assignments, role and profile overrides) and the `TenantSecurityModel` built from it over the stored IdP directory snapshot. It fails closed: no setting, or one that cannot be read, is the empty model. `Invalidate` bumps `Generation` and raises `Changed`, which stales every cached scope and keyset cursor. Every write (admin save, deploy prune) runs inside `Exclusive`. The admin save (`AdminService.SetSecurityModel` over `EnvironmentSecurityAdmin`) checks a candidate structurally (S3 `SecurityModelValidator`) and then against the deployed packages (`SecuritySettingCatalogCheck`: unknown role / profile / concept, unsecured field, depth on an organisation-owned concept, an override on an external concept or of System Administrator). A refused save leaves the stored setting unchanged. A Development tenant refuses the setting.
- **Scope rules.** `EnvironmentScopeRules.Records` = `SystemFieldGuard.Guard(Tier1ScopeCompiler.Compile(principal, catalog.Security, model, catalog))`. A record is visible when a role the caller holds, directly or through a team, grants read at a depth covering its `owner` / `owningBusinessUnit` (User: the caller or a team the caller belongs to owns it; BU: the source's unit; BU+children: its subtree; Org: any). A team-held role is judged at the team's unit (PR5). A share widens only privileges the grantee already holds at some depth (S3 R3). A secured field without a profile granting read is nonexistent to the caller, in projections and filters alike. An edge concept is visible only when both endpoints are, so a hidden record is never returned, reached or counted (PR4). Linking needs Append on the source and AppendTo on the target (PR3). The system fields are read-only in every scope, the System Administrator's included (PR1). Connector-bound concepts get no entries: their rows are outside the model (spec section 6).
- **IdP directory sync.** `IdpDirectorySyncHost` (`idp-directory-sync-host.ts`, via `PragmaticServer.DirectorySync()`) runs S3's `IdpDirectorySync` when the Runtime server starts serving, after each admin save and every `IntervalMs` (5 minutes). It invalidates the setting only when the pulled snapshot differs from the stored one in user states or group members (not the timestamp) or deprovisions someone, so an unchanged poll never stales cursors. A run never rejects: a failure, including a setting the store cannot read, is reported by error name. Server dispose waits for an in-flight run (`Stop`). Synced team members come from the snapshot's group members; manual rows stay in the setting, so a member removed from the IdP group keeps the manual row's access (`TeamMembershipRows`; `admin/team-members/list` shows each row with its origin). A disabled or deleted identity gets a deny-all scope. The local IdP is authoritative: a principal with no local account reads as Deleted. Deprovisioned ids are raised on `Deprovisioned`, which `CallerCredentials` follows to drop per-user source credentials (R27).
- **Catalog and admin reads.** `SecurityCatalogReader` (`security-catalog-reader.ts`) turns the environment catalog's `Security` into `SecurityCatalogDto`: base roles first with the union of package contributions as defaults, then package roles; engine-stored concepts with their `owned` flag; secured fields; profiles. It backs `admin/security-catalog/get` and the deploy diff.
- **Acting principal.** User requests run as the caller. Work no user started runs under `SystemPrincipalScope` (`system-principal-scope.ts`, via `PragmaticServer.SystemPrincipal()` / `SystemScope()`): `system:<environment>`, System Administrator at the root unit, no RBAC grants, so it never passes the `PolicyGate`. Today only the deploy ownership backfill uses it (`DataChangedPush` reads under `CallerConnectorContext.System` directly); future background work (connector population, scheduled flows, agents, identity resolution) must run under it. Every engine call carries the caller's connector context (`CallerConnectorContext`); a caller's-identity connection (`credentials = caller`, `tokenResource`) runs each caller's reads and writes on that caller's own source token and inner connection (`CallerCredentialAdapterFactory`, PR12). A dedicated-credential connection ignores the caller.
- **Deploy and promote.** `DeliverySecurity` (`delivery-security.ts`) computes `SecurityDeployDiff` between the running and the prospective catalog, prunes what the prospective catalog cannot mean from the stored setting before the swap, swaps catalog and security as one snapshot (an in-flight reader keeps the old ones), backfills newly owned concepts to the system principal and appends the diff to `SecurityChangeLog`. A non-empty diff is returned as `AppDeployResultDto.securityChanges` and listed by `admin/security-changes/list`. Overrides on concepts the upgrade keeps survive it; a dropped override or removed role assignment does not come back when a later deploy restores its concept.
- **Environment creation.** The control plane seeds a new Runtime environment's setting with one root unit and one System Administrator (`EnvironmentService.Create(..., creatorPrincipalId)`, `EnvironmentSecuritySeed`), and rolls the create back when seeding fails. Only a Runtime environment created with a creator is seeded (PR13: never a Development one; a create without a creator, such as a platform-admin route or the smoke, is left unseeded). Who is seeded depends on federation (ruling R39): a federated environment (the create registered an OIDC client at the tenant IdP) seeds the creator, who signs in through that IdP and is kept by the non-authoritative directory; an unfederated one (no hive, or an in-cluster hive with no base domain) has only local accounts and an authoritative local directory, where the creator has no account and would read as Deleted, so it seeds the bundle's bootstrap local admin (`BundleBuilder.AdminPrincipalId`, `admin`) instead.
- **Retired tier 2.** Gone with no compatibility path: per-app `access-policy.json` and model policy declarations, the policy compiler and catalog, the app-private concept bypass, the per-concept depth compiler and tenant read-authorization source, read-filter and field-read-mask sources, ownership-from-field rules and their resolver, membership claim rules, the old field-security and role sections of the setting, and the tier-1 engine catalog adapter. S3's `SecurityModelMigration` rewrites an old-shape stored setting once on open (PR18). That is a one-time migration, not a runtime shim.
- **End-to-end proof.** `src/tests/e2e/security-capstone-e2e.test.ts` runs the spec's user cases (section 9.1 to 9.5, section 5 edges) through real `PragmaticClient`s, the admin wire and the local IdP with groups. Section 9.5 drives the control plane's create through an in-process host. The scope invariant suites check every endpoint against the engine scope.

## Platform-security amendment (A1 to A8)

The plan was amended on 2026-11-11 for platform security (tier 1 only); the amendment wins over any ruling text it contradicts. A1: tier 2 is gone, with no `access-policy.json`, no model `policy` declarations, no policy compiler on either purpose and no app-private concept bypass. A2: `IPreparedRules` is `Records` / `Finish` / `Placement` / `Digest`; `AccessScopeSource` composes no policy or depth itself. A3 (superseded by security S4 Task 9): the runtime `Records` is the tier-1 compiled scope of the environment security setting (connector concepts fall to Default Allow); `Finish` fixes grants, read-only bindings and seeded nodes. A4: share, unshare, list and assign on an external record are refused with "external records are outside platform security". A5: the tier-2 tests are replaced by depth, external-concept, policy-files-ignored and security-edit-stales-cursor tests; the environment fixture writes no policy files. A6: `connector/*` reads and writes of connector-bound concepts are not gated by `Records`. A7: the runtime scope-invariant fixture uses depth-governed engine concepts plus an external binding visible to every principal; security S4 Task 9 rebases it on tier 1. A8: the R117 MalformedPolicy item (whole-app fail-closed on a malformed policy) is not adopted, because tier 2 is retired.

## Declared behaviour changes (M2.3)

The consolidated list of what a client or operator sees differently from the legacy runtime graph. Details sit in the sections above.

1. **`data/write` is atomic (Q3, S10).** A batch is one engine transaction: engine-stored ops are all-or-nothing, a failing op gets its status and every other op `failed` "atomic batch rolled back". External ops are written through at commit and compensated in reverse on failure (R9, best effort; a failed compensation is `CompensationFailed` and reported to diagnostics, R113). The legacy writer applied op by op per binding group.
2. **Keyset cursors are not staled by commits (S11).** A commit between two `cypher/query`, `connector/read*` or runtime `model/view` pages neither repeats nor skips a row. A cursor goes stale on a schema upgrade, a security-setting edit or another principal. On dev, every `cypher/execute` write saves the `.todl` sources, which upgrades the engine, so a dev cursor still stales after a write.
3. **Offset-paging fallback (Q10).** A query whose `ORDER BY` uses an expression that is no returned column has no keyset cursor and pages by offset: a commit between its pages may repeat or skip rows.
4. **Runtime `modelId` (S12, R53, R58).** `cypher/query`, `cypher/execute` and `cypher/models` accept a delivered package id on a runtime tenant (`cypher/models` lists them, sorted, `todl.system` excluded); the filter means "this package's data". Model-scoped reads exempt `todl.system.ShareGrant` (R58) so shared records stay visible, which means a model-scoped `cypher/query` or `connector/read*` can return the caller's own grant nodes. `model/view` uses the owner-only filter (R53: another package's taxonomy terms are not its members) and drops grant rows (R59; a page may be short).
5. **Runtime `model/view` and `model/resources` (S15).** `memberId` is a package id; items are the package's engine nodes (no schema, model or class nodes, no provenance); access depth and field security now apply (audit defect 3 closed); `model/resources` is always empty.
6. **`connector/decisions` answers empty (Q4).** The engine federates per binding and merges nothing; identity resolution is a separate design.
7. **`connector/writeBack` `dirty` is a no-op.** Writes commit when made; a non-empty `dirty` set returns diagnostic `NothingToFlush`. `deleted` ids are deleted in one transaction under the caller scope (closes audit defect 2) together with their share grants (R49).
8. **External filters (P10).** Only `eq` / `in` on String or Boolean members, `isNull` / `isNotNull`, id lookups and reverse FK lookups are pushed to the source; `neq`, ranges and every term on an Int64, Float64 or temporal member are evaluated by the engine over every fetched row, so a numeric filter over a large table fetches the whole binding.
9. **External writes and read-time OCC (engine 0.3.0; R15, R16, R48, R50).** The O1 ruling as taken: the host builds on `GraphTransaction.Fetch` (plan option (a)); updates and deletes of an external record fetch its row in the transaction and carry its read-time version. `connector/writePaged` honours a non-null `expectedVersion` (R16: the fetched version must match, else `conflict`); its results carry no `version` (R50: the engine does not yet report written source versions, so clients re-read). A delete of an absent key is `applied` (R48). The M2.1 D7 position (external writes without read-time OCC, a commit-window guard only) no longer applies.
10. **Client id on create (R38) and required fields (R39).** `data/write` honours a client `id` on create (the engine node's public id, or the external binding's id value); a create naming an existing record is `denied` (legacy upserted). Required-field validation reads cardinality from the TODL catalog.
11. **Grants on unreadable records no longer authorize (R41, R44).** An Update-, Delete-, Share- or Assign-only grant on a record the caller cannot read no longer authorizes `data/write`, share or assign (the in-transaction read sees nothing: `denied` or `not-found`). External records: share, unshare and assign are `invalid`, list is InvalidParams (A4, R43).
12. **Orphaned grants (R45, R46).** A user Cypher `DETACH DELETE` leaves the grant node; it widens nothing and a re-share rewrites it. `data/shares/list` skips stored grants with an unknown kind or empty subject.
13. **`data/changed` (S16, R54, R57).** New notification `{ commit, concepts }` on runtime connections: concept-level (a concept covers its subconcepts, no ids), filtered by the connection's scope reach, coalesced over 50 ms; `commit` is a monotonic watermark that may repeat, not a payload id. Because grant widening reaches every engine-stored concept, most are "maybe yours" and only constant denials are filtered (R54). A reopen pushes the root `todl.Element` (R57). External sources changed outside the engine are not pushed.
14. **Reopen fails in-flight readers (R25).** When a delivery changes the external connector set the runtime engine is disposed before the next opens on the same LMDB path, so a reader handed out before the reopen fails with `Disposed`. Dev retires the old engine after a grace period instead.
15. **Environment store and LMDB volume (Q7, S2).** The runtime graph lives in `<baseDir>/<environmentId>/graphs/environment-engine`. A cluster deployment must put the tenant base dir on storage the next lease holder can reach; otherwise a new holder opens an empty store. The helm chart is unchanged.
16. **Dead on-disk data (S17).** `applications/<app>/data/` (built-in documents, the `__shares` collection or `store.sqlite`) and any previously built environment instance are never read or imported; an operator may delete them.
17. **`application/open` (S7, Q1).** Refuses an application without a live pointer (InvalidParams "no live application named ..."); binds only the app, which `data/write`, `data/share|unshare|shares/list` and `data/assign` require; it never narrows or widens the scope.
18. **Owned-concept placement (R35, security S4 Task 9).** With identity, an owned concept created at runtime is stamped with the acting principal's `owner` and home business unit (`PrincipalFacts`); without identity nothing is stamped.
19. **`FederatedModelDataConnector` retired from TODL (R60, todl#27, todl 0.60.0).** The server never used it or `ConnectorWorkingCopy`; both are now deleted. TODL's package generator emits `BundledModelDataConnector` over the embedded shard for connector-backed models too (the environment engine re-derives connector resolution at runtime from the shard's connector/population metadata), and the connectors-host e2e was migrated onto the engine `DataSourceConnector` path.
20. **Tier 2 is retired (A1 to A8)** and write-only members (hidden but writable) are unsupported; see the amendment above and "Dev graph behaviour changes" for the dev-side differences.
